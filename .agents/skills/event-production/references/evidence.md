# 史料依据

每个实际维护的事件事实都应能由 claim 回到原始出处与必要摘录。只保存核查所需材料，不要求完整网页、命令输出、研究叙事或执行日志。

- classic：可核查原典、正史、政书与可靠数字化古籍。
- modern：可核查学术著作、专题史、论文与现代考证。
- database：用于发现线索和对排异说，不能单独支撑年份，也不能充当第二条独立可靠出处。

根据问题选择检索顺序；有本地 `raw/` 原典可直接核对，不固定 Web-first。网页是载体，不因两个 URL 就算两条独立出处。记录原书卷篇或页码，引用必要的短摘录，并说明证据支持哪一项事实。

canonical sources 保持 work、part、note、kind 契约。URL 和摘录放工作材料；本机文件路径不写入 canonical 出处。

非军事新发布和存量修订都需要两部不同 work 的可靠独立出处，至少一条 classic；工具检查不同书名，审核者检查实质独立性。军事事件可以一条强主出处，需支持已维护的年份、参战方、人物、结果等事实。result 未维护时不虚构结果。

史料冲突应反映在 accuracy、note 与候选说明中。审核者不能确认处理是否合理时返回 needs-evidence 或 needs-decision。未知人物、疑似重复、未确定组成关系都保留具体问题，不猜 id，不按年份推导 polity。

已完成批次保留支持正式内容的依据与审核结论。旧 `.harness/` 或 cards 材料可读；只有能回到真实出处的内容才可支持新的候选。
