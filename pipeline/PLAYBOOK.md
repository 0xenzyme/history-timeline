# 内容体例

站点只渲染。人物、关系、章节和出处写在 `pipeline/`，由 `npm run content` 编译成 `public/data/`。**不要手改 `public/data`。**

```powershell
npm run content        # 编译并写入 public/data
npm run content:check # 校验源数据，并确认生成文件未过期
```

新专题只走管线：登记人物 → 编排专题 → 编译。契约是 `contractVersion: 1` 的自包含 JSON；内部登记表可以更富（出处、别名、专题文案覆盖）。将来换合同，改编译器，不必重做考证。

## 目录

| 路径 | 职责 |
|---|---|
| `vocab/` | 地区、朝代、主题词表。新词先入表，再给专题挂上 |
| `registry/people/` | 一人一文件。生卒、accuracy、出处只在这里维护 |
| `topics/<id>/topic.json` | 泳道、收录、关系、事件、章节；可覆盖 display / bio |
| `topics.json` | 专题发布顺序 |
| `schema/` | v1 合同与人物登记的 JSON Schema |

## 谁进专题

收录分两层。阅读层决定这一章出现谁，底册层决定这个专题收录谁。打开专题仍进叙事章。全览和搜索使用底册。

### 阅读层

一章收 12–20 人。一个人出现在这一章，至少满足一条：

- 这一章少了他，结构会塌（例如武帝章没有霍去病）
- 他撑起一条必须看见的关系（师承、敌对、托孤）
- 生卒条本身就是这一章要教用户读的东西（短命与长命的对照）

`brief` 只写这一章在图上能看见什么。章节 `people` 从底册里点名。汉代样板仍可以只用较少的人讲清一条结构。

### 底册层

一个人进入专题，满足任一即可：

1. 该朝标准帝王序列，含实际称帝者。
2. 占一个结构席位，并且有可引用的生年或卒年（`exact` 或 `approx`）。只有岁数、没有年份的，不进底册。
3. 某一章的阅读层已经需要他。

席位各朝共用。一人只占一个席位：

- **帝王**：标准序列。
- **后妃 · 外戚**：每位皇帝一位实际皇后或掌权者；废立、立储、政变的直接当事人另收。
- **宰相**：主持过一个执政期（宰相任上跨三个年头及以上），或主持过一件已经画上轴的制度或战事。短命的同平章事不因官名自动进入。
- **将帅**：已画战争的双方主将，加上改变版图或藩镇格局的人。
- **文学 · 艺术 · 宗教 · 技艺**：有传世作品、生卒可定的人，一门数人到十余人。
- **宗室**：进入储位之争、起兵或实际出镇的亲王。
- **对立面**：轴上事件的另一方首领，包括叛首、割据始祖，以及与本朝交兵并改变版图的外族首领。

世系表和宰相表里的名字，要先占到席位并有生卒，才进入底册。附传子侄要自己占到席位。只有任官年、没有生卒的，不编年份。孝友、隐逸、酷吏、四夷全录，要被席位点中才收。

泳道按职能命名，如「宰相」「将帅」。

底册规模是规则跑完后的检查线，先定额再填人会把席位写松。短朝大约 50–80 人，中等长度的朝代大约 100–160 人，唐、宋、明、清大约 200–300 人。明显偏离时先改席位定义，再动登记。三次试跑都写在 `docs/`：唐朝见 `docs/tang-seats.md`，卒年句里写明年份的人比检查线少；元朝见 `docs/yuan-seats.md`，人数过线是因时间窗自大汗开国起算，而非放宽席位；明朝见 `docs/ming-seats.md`，内阁诸臣尚未与宰辅年表逐条比对，因此仍在 200 人以下。

## 生卒

`exact | approx | disputed | unknown` 必须跟材料一致。

- 有异说：`disputed`，并写 `birthNote` / `deathNote`
- 不详：年份留空，accuracy 为 `unknown`
- 约略：`approx`，有依据再写 note
- 禁止用一个整数假装精确

生卒只写在人物登记里。专题不得覆盖年份。同一人出现在多个专题，只改 `lane`、`display`、`title`、`bio`、`tags`、`order`。

## 关系

重叠由生卒年算出来，不入库。只录有叙事意义的边：君臣、师承、亲族、同僚、敌对。

每条关系必须有 `note`，能一句话说清为什么值得画。管线可以以后输出「同时代候选」，但候选不得直接写成 `relations`。

## 章节

`views` 是产品，不能从词条生成。每章必须有：

- 时间窗 `from` / `to`
- 焦点人物 `focus`
- 教用户怎么读图的 `brief`
- 需要收窄时，写出 `people` 与 `events`（省略等于全收）

`brief` 写这一章在图上能看见什么，不要写成时代概述。

## 文案

`bio` 两三句，服务读图：身份、和轴上其他人的关系、为什么出现在这一章。不要粘贴百科。

专题覆盖用于换角度，例如董仲舒在汉代专题称「董仲舒」，在儒学专题称「董子」。生卒仍是同一条登记。

## 出处

出处只存在管线源文件，不进入 v1 运行时 JSON。

格式：书名 + 卷篇，或现代考证的书名与页码。一人至少一条。外部数据库（Wikidata、CBDB 等）只作候选，必须经人审再写入登记表。

## 词表与分面

- `region`：国家或地区，一个专题只能属一处
- `eras`：可多值。跨时段主题（儒学）把经过的时代都挂上
- `themes`：`dynasty`（王朝）、`thought`（思想）等。新主题先加词表

不要做成「国家 → 朝代 → 专题」的死树。站点按三个分面过滤专题列表。
