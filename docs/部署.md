# 部署说明

本仓库**不包含**任何托管平台配置。仓库里没有 Cloudflare Pages、Netlify、Vercel 或 Docker 的部署文件，也没有部署工作流。本文只说明可复现的构建与发布步骤，不指定具体平台。

## 产物形态

- `npm run build` 输出静态站点到 `dist/`。
- `vite.config.ts` 使用 `base: './'`，`dist/index.html` 引用相对路径资源，因此站点可以挂在域名根路径，也可以挂在子路径。
- 路由使用 URL hash（如 `#han/wudi`、`#military/event/xianyang-zhi-zhan`），不依赖服务端路由重写。
- 运行时不读取环境变量。数据来自构建时生成的 `public/data/*.json`，构建时整目录复制进 `dist/data/`。
- 没有服务端组件、数据库、定时任务或第三方 API 依赖。

## 复现步骤

1. 确认 Node.js 22 或更高版本。
2. 安装依赖。

   ```bash
   npm ci
   ```

3. 运行门禁。

   ```bash
   npm test
   npm run build
   ```

4. 确认产物。

   ```bash
   ls dist
   npm run preview
   ```

5. 打开预览地址，检查首页、深链（`#military`、`#han/wudi`）、搜索、导出与两套皮肤。

## 发布步骤

任选一种静态托管方式，把 `dist/` 目录整体上传即可。

- 手动上传本地构建的 `dist/`。
- 或从 GitHub Actions 的 `CI` 运行下载 `dist` artifact。仓库使用 `actions/upload-artifact`，保留 14 天。

```bash
gh run download <run-id> --name dist
```

发布后不需要额外配置。若托管平台默认对未知路径返回 404，只需确认 `/data/*.json` 与 `/assets/*` 可访问；hash 路由不会请求服务端路径。

## 已知边界

- 仓库无法证明线上站点由哪一次提交发布。需要发布记录时，以 `dist` artifact 对应的 workflow run 为准。
- 顶层 `raw/`、`design/`、`prototype/` 不进入构建，也不会出现在网页产物中。
