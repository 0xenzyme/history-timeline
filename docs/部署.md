# 部署说明

站点是纯静态产物。主路径使用 GitHub Pages 与 GitHub Actions 部署，Cloudflare Pages 作为备选。

## 产物形态

- `npm run build` 输出静态站点到 `dist/`。
- `vite.config.ts` 使用 `base: './'`，`dist/index.html` 引用相对路径资源，因此站点可以挂在域名根路径，也可以挂在子路径。
- 路由使用 URL hash（如 `#han/wudi`、`#military/event/xianyang-zhi-zhan`），不依赖服务端路由重写。
- 运行时不读取环境变量。数据来自构建时生成的 `public/data/*.json`，构建时整目录复制进 `dist/data/`。
- 没有服务端组件、数据库、定时任务或第三方 API 依赖。

## 复现步骤

1. 确认 Node.js 22 或更高版本。
2. 安装依赖。

   ```bash
   npm ci
   ```

3. 运行门禁。

   ```bash
   npm test
   npm run format:check
   npm run build
   ```

4. 确认产物。

   ```bash
   ls dist
   npm run preview
   ```

5. 打开预览地址，检查首页、深链（`#military`、`#han/wudi`）、搜索、导出与两套皮肤。

## 主路径：GitHub Pages（Actions 部署）

### 用户需要先做的一步

在仓库 Settings → Pages → Build and deployment → Source 中，把发布来源改为 **GitHub Actions**。该设置无法由仓库文件代替。

### 仓库内的配置

`.github/workflows/pages.yml` 在推送到 `main` 时执行：

1. `npm ci` 与 `npm run build`。
2. `actions/configure-pages` 与 `actions/upload-pages-artifact`，上传 `dist/`。
3. `deploy` job 使用 `actions/deploy-pages` 发布，权限为 `pages: write` 与 `id-token: write`，环境为 `github-pages`，并发组为 `pages` 且不取消进行中的部署。

全套门禁（`npm audit`、`npm test`、`npm run format:check`）由 `.github/workflows/ci.yml` 在 push 与 PR 上执行。`pages.yml` 只跑构建，避免同一提交重复跑两遍测试与格式检查。取舍是：部署不再等待测试结果，若测试失败，回滚需要重新发布。

### 访问地址

- 默认项目页地址：`https://0xenzyme.github.io/history-timeline/`。
- 子路径必须带尾斜杠。访问 `/history-timeline`（无 `/`）时，相对资源路径会解析到域名根目录，导致资源 404。GitHub Pages 会自动重定向到带斜杠的地址，其他平台需自行配置。

### 自定义域名

1. 在 Settings → Pages → Custom domain 填写域名并保存。
2. 在 DNS 添加记录：子域使用 `CNAME` 指向 `0xenzyme.github.io`；根域按平台提示添加 `A` 记录。
3. 等待验证通过后勾选 Enforce HTTPS。

自定义域名的地址应与 `package.json` 的 `homepage`、`index.html` 的 canonical 与 `og:url` 保持一致。当前仓库仍写 `https://history.0xenzme.dev`，待域名确认后同步。

## 备选：Cloudflare Pages

1. 在 Cloudflare 控制台 Workers & Pages → Create → Pages → Connect to Git，授权并选择本仓库与 `main` 分支。
2. 构建设置：Build command `npm run build`，Output directory `dist`，环境变量 `NODE_VERSION=22`。
3. 在 Pages 项目 → Custom domains 绑定域名；域名托管在 Cloudflare 时 DNS 自动写入，否则在域名商处添加 CNAME。
4. 如需精确缓存头，可在 `public/_headers` 写入规则，构建后会复制到 `dist/_headers`。

## 缓存建议

| 路径 | 建议 |
|---|---|
| `/assets/*` | 文件名带内容哈希，可设置长缓存，例如 `public, max-age=31536000, immutable`。 |
| `/data/*.json` | 文件名固定、内容随每次内容更新变化，使用协商缓存（`no-cache` + ETag），或设置很短的 `max-age`。不要长缓存。 |
| `/index.html` | 短缓存或不缓存，保证新版本入口及时生效。 |
| `/images/*` | 文件名不变时使用短缓存；改名后可长缓存。 |

GitHub Pages 不提供自定义响应头，无法精确控制以上策略，实际使用平台默认缓存。需要严格缓存控制时使用 Cloudflare Pages 的 `_headers`。

## 已知边界

- 仓库无法证明线上站点由哪一次提交发布。需要发布记录时，以 `Pages` workflow run 与部署环境记录为准。
- 顶层 `raw/`、`design/`、`prototype/` 不进入构建，也不会出现在网页产物中。
