# 人物收录工作流审查

- 审查日期：2026-10-01（本次）
- 范围：**工作流**——一个人物从「被发现」到「在站点上被画出来」的完整链路，以及这条链路上的规则是否被机器兜住
- 与 `05-收录规则审查.md` 的分工：05 审查的是**规则文本**（收录席位、生卒、关系、章节、polity 口径）；本文审查的是**规则的执行链路**。05 的结论在本轮做了复核，见第四节。
- 评判基准（业主给定）：
  1. **尽可能多地收录**——规则不应把可考的人挡在门外，规模上限不是目标而是结果
  2. **准确**——年代、归属、身份不能错；宁可标 `unknown` 不可编造；史料模糊者在人物信息中说明，必要时可参考外界资源

## 3. 卡住「多收录」的三处

### W1【high】候选池只有西周一层，其余 16 个专题没有草稿层

- 证据：`cards/` 下只有 `README.md`、`schema.md` 和 `cards/西周/`（131 张），全库 `*.ts` grep `promoted|cards/` 零命中——没有任何脚本把卡片晋升为登记。
- 后果：新增一个人 = 全程手写 registry JSON。1551 人里除西周外约 1420 人是这么来的。
- 失分：**多收录**。产能瓶颈不在规则，在没有起草层。

### W2【high】trial 候选池写完了，但没有转化机制

- 证据：`docs/seats/chunqiu-trial.md:3` 试跑目标「约 236 人」，:13-43 逐席列出 213 名新增候选；如今 chunqiu 专题实收 **82** 人。trial 与 seats 都是人写的 md，没有清单文件、没有定期跑的环节；`harness/intake.md:18` 把「春秋到隋、南北朝按席位补底册」标为 P3「当前目标不做」。
- 后果：候选池是一次性产物，写完就沉底。10 篇 trial 里的候选总量没有汇总，也没人知道剩多少没落库。
- 失分：**多收录**。

### W3【high】生卒门槛把核心叙事人物挡在门外，且与「模糊可说明」的原则冲突

- 证据：PLAYBOOK《底册层》条件 2 要求「有可引用的生年或卒年（`exact` 或 `approx`）」，且明确「只有岁数、没有年份的，不进底册」。`docs/seats/chunqiu-trial.md:54` 是这条规则的实际代价——**赵盾、孙叔敖、华元、季札、老子、师旷、曹刿** 等因卒年不可定被排除，试跑者自己写下「赵盾、孙叔敖、华元、季札是核心叙事人物……这是本底册最大内容缺口」。另：`disputed` 未被列为有效生卒（05-C，本轮复核仍成立）。
- 后果：规则逼人二选一——编一个整数假装精确，或不收。前者违反准确，后者违反多收录。
- 失分：**多收录 + 准确**，两条原则同时违反。
- 注：西周已经有一种事实上的解法——约 60 条把「活动下限」写成 `approx` 并在 `deathNote` 写明「卒年不详」（`04-内容.md:82`）。但这是惯例，规则里没有这个入口。

## 4. 卡住「准确」的四处

### W4【high】外部资源实际使用率为 0，且规则没给它们留位置

- 证据：全库 grep `wikidata / CBDB / 维基 / 百度百科` 仅 3 处命中，且都在说明文字里（PLAYBOOK:111、cards/README.md:67、docs/seats/han-trial.md:39）。registry 的 `sources` 100% 是典籍 `work/part`（如 `ji-hu.json:14-23` 只有《史记·周本纪》《国语·周语上》）。`person.schema.json:22-35` 的 source 只有 `work/part/note`，没有任何来源类型字段。
- 后果：先秦、五代十国、北朝这类史料模糊的人群，取证路径只有「翻 raw 里的典籍全文」一条。而 PLAYBOOK 只写了「外部数据库只作候选、须经人审」，没写怎么用、写在哪、审完记在哪。
- 失分：**准确**，并直接违背业主「必要时可以参考外界资源」的给定口径。

### W5【medium】schema 是死文件，lint 只兜住必填项

- 证据：本轮 grep 全项目 `person.schema` 仅 4 处命中——`cards/schema.md:3`、三份 review 文档，**没有任何 `.ts` 引用它**。05-B 成立。lint 实际校验的是：词表存在性、出处非空、accuracy 组合、关系 note、章节 brief/focus（lint.ts:10-56/112-129）。底册席位、一人一席、polity 归属对错、章节人数一律不校验。

### W6【medium】cards 与 registry 已分叉，且文档过期

- 证据：`cards/西周/ji-hu.md` 卡片 YAML 有 `deathNote`（共和十四年），registry 的 `ji-hu.json` 卒年 `exact -828` 且无 `deathNote`（`04-内容.md:14` 已记录）。此前版本的 `cards/README.md` 曾写「专题 14 人」；该数字已在本轮修复记录中改为 131 张，见本文第 8 节。
- 后果：同一人有两套正文，无同步机制，卡片里考出来的东西不会自动回到登记。

### W7【low】登记了却没进任何专题，只有 warning

- 证据：`lint.ts:145-149` 对「已登记但未被任何专题收录」只出 warning；`cli.ts:25-28` 的 warnings 只打印不阻断（exit 1 只由 errors 触发）。
- 后果：人可以躺在 registry 里永不上轴，且没有清单沉淀——只能靠人看终端输出。

### W8【medium】polity 多值没有可复现的判据，且「东汉」在词表里不存在

- 证据一（判据失效）：同为「汉末起家、后开国」的人处理不一致——`cao-cao.json:7-10` 是 `["han","wei"]`、`liu-bei.json:7-10` 是 `["han","shu"]`，而 `sun-quan.json:7-9`、`sun-jian.json:7-9`、`sun-ce.json:7-9` 只有 `["wu"]`。孙坚、孙策与曹操一样同时进东汉专题（泳道 `qunxiong`，`donghan/topic.json:492-502`）和三国专题，按 PLAYBOOK「占两条脉络」该是双值，实际单值。所以真正在决定双值的不是「被两个专题收录」，而是人工特例。
- 证据二（来源拼合）：`infer-taxonomy.ts:110-112` 由 tags 精确匹配填 `wei/shu/wu`（曹操 tags「曹魏」→wei，孙权 tags「孙吴」→wu），而 `han` 这一半是人工后加。双值是两层来源拼出来的，不是一次判断的产物。
- 证据三（词表缺口）：`vocab/polities.json` 无 `xihan`/`donghan`，只有 `han`（汉）。刘秀（`liu-xiu.json:11-13`）与刘邦共用 `han`。「曹操算东汉」在 polity 层无法表达；`han` 也指西汉。
- 失分：**准确**（归属不可复现、不可校验）。
- 与 05-D 同源：PLAYBOOK 的口径是「看叙事脉络」，实现是「tags 关键词」，两套哲学。

## 6. 建议修改顺序（成本从小到大，先服务多收录）

1. **W3 改门槛**：把底册条件 2 从「必须有 `exact/approx` 生卒」改成「有可引用的年份锚点即可」——`disputed` 计为有效生卒；仅有活动年/事件年者，允许以该年作 `approx` 并在 `birthNote`/`deathNote` 写明「活动下限，非寿数」。把西周已有的惯例写成规则。
2. **W4 给外部资源留位置**：`sources` 增加来源类型（典籍 / 现代考证 / 数据库），规则写明「数据库只作候选，写入前须回原典或经人审；异说一律 `disputed` + note」。解锁先秦、十国的模糊人群。
3. **A 检查线改口径**：固定人数带改为「席位覆盖下限」；多国时代（春秋、战国、南北朝、五代十国）单列一档，不要再让试跑者自行论证。
4. **W2 候选池清单化**：每篇 `*-trial.md` 顶部固定写「候选 N / 已落库 M / 不收 K」三个计数，并把「春秋到隋补底册」从 intake 的 P3 里捞出来排期。
5. **W5 接回 schema**（或删除），**W7** 让「登记未收录」能导出成清单。
6. **W8 统一 polity 口径**：按现有规则表把汉末开国者收成单值（曹操 `["wei"]`、刘备 `["shu"]`、孙权/孙坚/孙策 `["wu"]`）。「汉末群雄」这一层由东汉专题的 `qunxiong` 泳道表达。这个方案与刘邦→`han`、李靖→`tang` 的处理一致，不新增判据。

   若要保留双值，则须把判据写成「被两个专题同时收录 → 双值」，并回填孙坚、孙策、孙权。孙权须先进入东汉专题。还要决定是否把 `han` 拆成 `xihan` 和 `donghan`，这会影响 248 人。
7. **W1/W6**：决定 cards 层的去留。要么把它补成通用起草层并编写晋升脚本，要么明确它只是西周的历史草稿，事实源只有 registry，并同步更新 README 与 schema.md。

## 7. 一句话

只改一处就改**底册门槛**：把「必须有 `exact/approx` 生卒」改成「有可引用的年份锚点即可，模糊者在 note 说明并标 `approx`/`disputed`」——它同时解锁多收录（赵盾、孙叔敖、华元、季札这批核心人物）和准确（不必再在「编一个整数」和「不收」之间二选一）。
