# 人物收录现状盘点

本盘点只读管线源文件，不改 content/、pipeline/、public/、src/。可由源文件重算。

## 口径

- **人数合计（Occurrences）**：`pipeline/topics/<id>/topic.json` 的 `people[]` 条数。同一个人被多个专题收录时按专题各计一次。
- **Markdown / registry JSON**：该条 `people[]` 对应的人物记录来自 `content/<topic>/<id>.md`（Markdown）还是 `pipeline/registry/people/<id>.json`（存量 JSON）。
- **无 profile**：存量 registry JSON 没有 `profile` 字段；`content/` 下人物 Markdown 全部显式写了 `profile`。
- **生卒缺失**：frontmatter 的 `birth` / `death` 缺省。accuracy 分布覆盖全部人物；PLAYBOOK 规定年份留空记 `unknown`，故 `unknown` 数≈缺失数。
- **polity 分布**：按人物 frontmatter 的 `polity` 数组逐值计数，多值人物在每个值上各计一次。
- **关系覆盖**：在该专题 `relations[]` 里作为 source 或 target 出现过的 `people[]` 人数；"无关系"为差值。
- **时间空档**：在该专题 `meta.range` 内，合并全部已收人物的生命区间（`birth..death`，单端缺失时用另一端），列出长度 ≥50 年、无任何区间覆盖的空隙。
- **悬空引用**：四类——relations[] 端点不在 people[]；people[] 的 id 在 `content/` 与 `pipeline/registry/people/` 都找不到；people[] 的 lane 不在 lanes[]；`content/<topic>/` 目录存在但不在 people[]。
- **事件交叉**：事件实体不记录专题（见 `docs/事件线规则.md`）。机械口径取「`meta.range` 与事件 `[year, endYear]` 相交的全部专题」为该事件的候选专题；`people`/`commanders[].id` 不出现在其中任一专题 `people[]` 即列为悬空。

仓库文档（AGENTS.md / PLAYBOOK.md）称还有 61 人留在 registry JSON；本次实测 `pipeline/registry/people/*.json` 为 **44 份**。
