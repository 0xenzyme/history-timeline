# 技术审查

审查日期：2026-09-26。范围是当前工作区，不是 git HEAD。

## 结论

可以接着用。`npm run build` 退出码为 0，TypeScript 类型与 `public/data` 的字段对齐，内容命令在校验失败前不会改写出目录。没有阻断项。最大风险是 `pipeline/schema/` 仍描述旧契约且构建根本不跑它；其次是跨公元的年份轴只在刻度上跳过 0，比例尺和岁数仍把 0 年算进去。分类脚本还有干跑写文件、两套覆盖规则，不在发布路径上，但会直接改登记。

## 现状

- 栈：Vite 6 + TypeScript 5.7（`strict`），无 UI 框架。依赖只有 `d3-scale`、`d3-selection`、`d3-zoom`。`vite.config.ts` 的 `base` 为 `./`，开发端口 5180。浏览器用 `fetch('./data/...')` 拉 JSON，不把数据打进包。
- 前端：`src/timeline/`、`src/ui/` 基本是纯函数，吃专题和状态、吐 SVG/HTML 字符串。`src/main.ts` 1025 行，独占加载、hash、缩放、拖拽、搜索、导出和关系图。缩放改的是年份 domain 后整图重画，不是 SVG transform。年份轴画在单独的 `#axis-pin`。
- 数据流：`pipeline/topics.json` 定顺序 → `load.ts` 读词表、`registry/people/`（618 人）、`topics/<id>/topic.json` → `compile.ts` 的 `mergePerson` 用登记生卒加专题泳道/文案，`primaryOf` 补主分类 → `validateCatalog` / `validateTopic` 加 `lintPipeline` → `public/data/index.json`、`search.json` 和 16 个专题 JSON。契约号 `contractVersion: 1`。`src/types.ts` 与 `pipeline/types.ts` 共用 `Accuracy` 等类型。
- 工作区相对文档和 HEAD：专题已从西周铺到清，另有儒学；分类是 `categories` / `primary` / `polity`，不再是人物上的 `role`。
- 命令：`dev`、`content`、`content:check`、`taxonomy`、`migrate`、`overrides`、`build`、`preview`。`build` 为两段 `tsc --noEmit`、`cli.ts --check`、`vite build`。三个分类脚本不在 build 里。没有测试脚本。源码里没有 `as any`。

## 问题

没有阻断项。

### 1. 高 · JSON Schema 与现行类型、运行时 JSON 脱节

位置：`pipeline/schema/person.schema.json`、`topic.schema.json`、`catalog.schema.json`；对照 `src/types.ts` 的 `Person` / `Catalog`，`pipeline/types.ts` 的 `RegistryPerson`。

证据：三份 schema 都是 `additionalProperties: false`。登记 schema 没有 `categories`、`primary`、`polity`、`gender`。专题 schema 的 `$defs.person` 同样没有。目录 schema 的 `required` 只有 `regions` / `eras` / `themes` / `topics`。工作区 618 份登记都有 `categories`，`public/data/index.json` 有 48 个分类，编译人物也带这些键。仓库内没有 Ajv，也没有代码引用这些 schema。真正的门是 `src/contract.ts` 和 `pipeline/lint.ts`。`load.ts` 的 `readJson` 使用 `as T`，`birthAccuracy` 不是运行时枚举：只要和「有没有年份」自洽，写错的精度字符串也能过 lint。

影响：类型和 `public/data` 没有字段漂移，名为契约的 schema 有。按 schema 校验会拒绝现行目录、专题和登记；不校验则这次分类改造对契约文件不可见。

### 2. 中 · 无公元 0 年只落实在刻度上

位置：`src/timeline/axis.ts` 的 `tickYears`，`src/timeline/layout.ts` 的 `buildLayout`，`src/format.ts` 的 `formatYear` 与 `lifespanSpan`。

证据：`tickYears` 在 `year === 0` 时 `continue`。比例尺是 `scaleLinear().domain([topicFrom, topicTo])`，-1 到 1 占两个年份单位。岁数用 `death - birth`。`formatYear(0)` 返回「公元元年」，与「没有 0 年」矛盾；数据里没有年份 0。范围跨过 0 的专题是汉代 `[-260, 23]` 和东汉 `[-5, 220]`。跨纪元 5 人：刘秀 -5..57、马援 -14..49、王莽 -45..23、王政君 -71..13、刘衎 -9..6，卡片岁数都多 1。

影响：这两条轴在公元前后被多拉开一年。放大到交界时，前 1 年与公元 1 年之间有一个空年。不跨 0 的专题不受影响。

### 3. 中 · 未知端不是 56px 开放条，相关分支不可达

位置：`src/timeline/geometry.ts` 的 `barGeom` / `barStops`，`src/timeline/bars.ts` 的 `renderBars`，`src/ui/legend.ts`。

证据：缺生年或卒年就走 `markerOnly`，菱形加约 14px 的 chevron。两端年份都在时 `leftOpen` / `rightOpen` 恒为 false，`leftKind` 只有 `exact` 或 `approx`。`barStops` 里 `open` 渐变没有调用方。注释写「两端均不知」，条件却是任一端缺失；两端皆空会被 lint 拒绝。图例「一端不详」画的是菱形，和代码一致。`FADE_APPROX` 为 16，代码里没有 56。登记 249/618 人只有一端年份。

影响：未知端不会在缩放时保持一段固定像素的开放条，只在已知年份放一个点。读 `barStops` 会以为开放条仍在生效。

### 4. 中 · 设计文档相对工作区过时

位置：`docs/设计方案.md`。

证据：文首仍是 v0.4，专题止于西周、春秋、战国、汉代、儒学；M8 只写到战国。约第 393 行仍称秦和东汉以下尚未开做。约第 145、360 行把 56px 开放条标为已验证。约第 374 行写当前专题全为公元前。目录说明只有 region / eras / themes，没有 `categories`。约第 346 行的体积是 JS 81 KB、CSS 6.7 KB；本次 build 为 JS 112.66 KB（gzip 38.02 KB）、CSS 14.68 KB。端口 5180 与 `vite.config.ts` 一致，这一点没过时。

影响：照该文档验收会漏掉分类字段和跨公元比例尺，并把已经改掉的条形当成通过项。

### 5. 中 · 分类脚本干跑会写文件，覆盖规则不一致；内容写出不原子

位置：`pipeline/infer-taxonomy.ts`、`migrate-categories.ts`、`apply-overrides.ts`、`cli.ts`。

证据：`content` 在 `compileAll` 抛错或 lint error 时直接退出，此时尚未 `writeFileSync`，不会先写坏 `public/data`。通过后逐文件写，不删多余文件，也不换目录；进程死在写入中途会留下半截 JSON。`--check` 只比对预期文件（当前 16 个专题无孤儿，且与编译结果一致）。`infer-taxonomy.ts` 无 `--write` 也覆盖 `taxonomy/todo.json`，日志却称未改动任何文件。`migrate-categories.ts` 在复核清单非空时写 `migrate-review.json`，同样不看 `--write`；已有 `categories` 的登记会跳过，现在 618 人都有分类且没有 `role`，再迁移对人物文件是空操作。`apply-overrides.ts` 校验失败不落盘，但写入仍逐文件进行。它用 `PROTECTED_IDS` 跳过陶弘景、阮籍、王莽；跨表时 categories 取并集，primary 留字母序在前的那张表。`infer-taxonomy.ts` 的 `readOverrides` 是后文件覆盖前文件，且不认保护名单。两套脚本都不写 `public/data`。`pipeline/vocab/roles.json` 已无读取方。

影响：build 不改源数据。手跑 taxonomy / migrate 会改登记或待办，干跑并不干净；同一张覆盖表两种脚本结果不同。content 的损坏窗口只在校验已经通过之后。

### 6. 中 · 路由只记住章节，加载中的 hash 会丢

位置：`src/main.ts`，`src/routing.ts` 的 `formatHash` / `parseHash`。

证据：hash 只有 `#topicId/viewId`。`focusId`、缩放 `domain`、关系图 `mode`、`showAllRelations` 和滚动都不进地址。刷新后 `applyView` 把视野设回章节窗口，焦点回到该章 `focus`（全览或窄屏则清空）。`onHashChange` 在 `loadingTopic` 时直接返回。缩放回调只 `render()`，`renderTimeline` 整段替换 `svg.innerHTML`；键盘焦点只在 `setFocus` 里用 rAF 抢回，缩放路径没有这一步。

影响：刷新、后退、加载过程中再改 hash，会丢掉焦点、缩放和关系图。新交互仍只能堆进这一个文件。

### 7. 中 · 没有测试，画法不变量不会让 build 失败

位置：`package.json` 的 `scripts`；设计方案第 9 节声称的无头断言。

证据：无测试框架，仓库里也没有可复跑的浏览器脚本。`build` 只做类型检查、引用/词表/生卒自洽，以及 `public/data` 与编译输出的逐字节比较。不检查比例尺是否跳过 0，也不检查条形像素。非空断言很少，集中在 `currentView` 的 `state!` 和 `buildAdjacency` 的 `map.get(a)!`。

影响：问题 2 和问题 3 这种退步仍然绿灯。本次 build 还有 69 条「没有关系」warning，不失败，真错误容易被刷掉。

### 8. 低 · 图例未走 `esc`；别名未进搜索

位置：`src/ui/legend.ts` 的 `renderLegend`；`pipeline/compile.ts` 的 `mergePerson` / `compileSearch`；`src/ui/search.ts` 的 `scoreFields`。

证据：卡片、搜索结果、章节、关系图、轴标签、条形和事件名都经 `src/timeline/svg.ts` 的 `esc`（`& < > " '`）。图例把泳道名、颜色、关系名和 `dash` 直接拼进 HTML/SVG。数据来自本仓库，不是外部输入。约 450 人有 `aliases`，编译出的 `Person` 和 `search.json` 没有该字段；搜索只看 display、name、title、tags。孔子因 name 为「孔丘」仍能搜到；「华阳隐居」这类别名搜不到。

影响：现行泳道名不含标记，图例不会马上坏。别名是搜索盲区。

## 构建结果

`npm run build` 退出码 0。顺序为站点 `tsc --noEmit`、管线 `tsc --noEmit -p pipeline/tsconfig.json`、`tsx pipeline/cli.ts --check`、`vite build`，均通过。content check 打印 69 条「没有关系，确认是否只为镜头收录」，然后是 `content check passed：16 个专题`。Vite 6.4.3 产出 `dist/assets/index-Cv87eEJO.js` 112.66 KB（gzip 38.02 KB，map 422.64 KB）、`dist/assets/index-C1HjA3v-.css` 14.68 KB（gzip 3.58 KB），`built in 241ms`。无错误输出。

## 建议

1. 改 `pipeline/schema/` 三份文件，补上 `categories`、`primary`、`polity`、`gender`，并在 `pipeline/cli.ts` 的 check 里真正校验；不跑就不要再把它当契约。
2. 在 `src/timeline/layout.ts` 的比例尺和 `src/format.ts` 的 `lifespanSpan` 去掉公元 0 年，不要只在 `tickYears` 里跳过刻度。
3. 在 `src/timeline/geometry.ts` 定一种未知端：恢复固定像素开放条，或删掉 `barStops` 的 `open` 死分支，并改 `docs/设计方案.md` 第 3.2 节，两套说法不要并存。
4. `infer-taxonomy.ts` 干跑不要写 `taxonomy/todo.json`；`readOverrides` 与 `apply-overrides.ts` 的合并规则和 `PROTECTED_IDS` 对齐；`cli.ts` 用临时目录整包替换 `public/data`。
5. 为 `barGeom`、`tickYears`、`parseHash` 加纯函数测试；在此之前，`src/main.ts` 至少不要在 `loadingTopic` 期间丢掉 `hashchange`。
