# 内容架构审查

审查日期 2026-09-26，对象是工作区（只读 pipeline 与 public/data，未重跑编译）。

## 结论

这套模型可以继续增加朝代。

新朝代不需要新契约。人物仍保存在 `pipeline/registry/people/` 中，每人一个文件。专题仍保存在 `pipeline/topics/<id>/topic.json` 中。新增专题时，还要在 `pipeline/topics.json` 中加入顺序，并在 `vocab/eras.json` 中加入时代词。

生卒年只保存在登记中。`compile.ts` 把登记和专题覆盖合成为 `contractVersion: 1` 的自包含 JSON。按这套规则回放，现有 `public/data/` 与源数据没有字段差异。`public/data/` 不是手工修改的生成物。

最大结构风险是身份存在三套写法，界面实际只使用泳道。

`categories` 和 `primary` 已经编进运行时，但界面不读取它们。`taxonomy/overrides/` 仍能把另一份分类写回登记。编辑备忘要求 `primary` 必须显式填写，不能按 `rank` 推导。编译器在字段缺省时仍按 `rank` 选择最高项，因此 286 人的运行时主分类不在源文件中。

地区和主题分面几乎没有筛选效果。它们不能阻止新增朝代，也不能支撑当前的导航需求。

## 模型

加载顺序在 `pipeline/load.ts`：先读 `topics.json`，再读五份词表和全部人物文件，然后按发布顺序读专题。人物文件名必须等于 `id`，重复 `id` 直接失败。`compile.ts` 的 `mergePerson` 只从登记抄生卒、accuracy、`categories`、`polity`、`gender`；`display` / `title` / `bio` / `tags` 有专题覆盖就整段替换，没有就用登记。年份不在覆盖字段里，现有专题人物条目也没有 `birth` / `death`。`primary` 若源文件没有，就用 `vocab/categories.json` 的 `rank` 现算。`lint.ts` 在写入前把关；`cli.ts --check` 只比对生成文件，不负责另一套 JSON Schema。同时代不入库，渲染时用生卒算关系锚点（`src/timeline/geometry.ts`）。

| 路径 | 职责 | 是否进入运行时 JSON |
|---|---|---|
| `pipeline/registry/people/*.json` | 一人一文件：生卒、accuracy、出处、别名、默认文案、`categories`、`primary`、`polity`、`gender` | 生卒、文案、分类、政权、性别进入人物对象。`sources`、`aliases` 不进入 |
| `pipeline/topics/<id>/topic.json` | 泳道、收录、`order`、可替换的专题文案；关系、事件、章节 | 整份专题文件。文案是替换，不是与登记合并 |
| `pipeline/topics.json` | 专题发布顺序 | 决定 `index.json` 里 `topics` 的顺序 |
| `vocab/regions.json`、`eras.json`、`themes.json`、`categories.json` | 目录分面，以及分类词和 `rank` | 全部进入 `public/data/index.json` |
| `vocab/polities.json` | 政权 id（40 条） | 不进目录。人物身上只出现裸 id |
| `vocab/roles.json` | 旧的单值 `role` | 不加载。登记里已没有 `role` |
| `taxonomy/lane-map.json`、`overrides/`、`todo.json` | 泳道推断和人工覆盖；`todo.json` 是缺口清单 | 不进入。`overrides` 与 `infer-taxonomy.ts` 可以把分类写回登记 |
| `pipeline/schema/*.json` | 纸面契约 | 编译不读取 |
| `public/data/*.json` | 目录、16 个专题、`search.json` | 就是运行时 |
| `cards/`、`raw/` | 人物草稿和史料正文 | 不参与编译 |

`lint.ts` 当前可以检查多项不变量。当前数据在这些检查上通过：缺出处、生卒皆空、accuracy 与年份矛盾、`disputed` 没有 note、分类或政权不在词表、`primary` 不在 `categories` 里、专题引用未登记的人、关系没有 note、章节没有 `brief` 或 `focus`，都会产生 error。

它不要求 `categories`、`primary`、`polity`、`gender` 必填。它也不检查政权顺序、标签是否重复写分类，以及关系 note 中的人名是否与 `target` 一致。没有关系只产生 warning（630 个专题收录中有 69 个，三国有 21 个）。

公元前用负整数，登记里没有年份 0。轴上「跳过公元 0 年」只做到刻度：`src/timeline/axis.ts` 在 `year === 0` 时不画刻度，比例尺仍是跨过 0 的 `scaleLinear`。

## 统计

人物分母是登记 **618** 人。专题收录 **630** 人次：12 人跨两个专题，没有「只登记、不收录」。关系 **623** 条。`public/data` 按现行合并规则回放，人物字段差异 **0**（含编译时补上的 `primary`）。这和源文件逐字相同不是一回事。

| 项 | 数量 | 分母与口径 |
|---|---|---|
| `categories` 非空，且都在词表内 | 618 | 618 登记人 |
| 登记里写了 `primary` | 332 | 618 |
| 登记没有 `primary`，运行时按 `rank` 补上 | 286 | 618；其中单分类 249，多分类 37 |
| 显式 `primary` 不等于 `rank` 推断 | 89 | 332 名写了 `primary` 的人 |
| `polity` 非空 / 缺失 | 594 / 24 | 618；缺失与 `taxonomy/todo.json` 一致 |
| `gender` | 556（男 537，女 19） | 618；缺 62，其中先出现在西周的 31 人 |
| `sources`、`bio` | 618、618 | 618；出处不进运行时 |
| 关系缺 `note`、悬空 id | 0、0 | 623 条关系；630 人次收录 |
| 多政权人数组顺序与词表下标不一致 | 0 | 21 名多政权者 |

抽查三个人，对照登记和两个专题的生成 JSON。

孔子（`kongzi`）生卒为 -551 / -479。春秋泳道为 `shi`，儒学泳道为 `ru`。登记没有 `primary`、`polity`、`gender`，运行时 `primary` 被补成 `scholar-official`（rank 46，高于 `confucian` 的 24）。

董仲舒生卒为 -179 / -104，`polity` 为 `han`。儒学专题把 `display` 改为「董子」，并整体替换 `tags`。汉代专题使用另一套 `title`、`bio` 和 `tags`。

朱元璋生卒为 1328 / 1398。`primary` 显式为 `monarch`，`polity` 为 `["yuan","ming"]`。元专题泳道为 `end`，明专题泳道为 `emperor`。三个人的生卒都没有被专题改写。

同名不同人已经有后缀先例：`ji-yijiu` 与 `ji-yijiu-jinghou` 都叫姬宜臼，但是两个 id。登记没有第二份「李泌」。

## 问题

**1. 高 — `primary` 的约定和编译器是反的。** 类型注释和 `compile.ts` 的 `primaryOf` 写明：缺省时按 `rank` 取最高分类。`infer-taxonomy.ts` 也故意不把 `primary` 落盘，留给编译层推。备忘里的「必须显式、不许按 rank 推」没有进 `lint.ts`，也没有进 `PLAYBOOK.md`。286 人的源文件没有 `primary`，`public/data` 里全都有。单分类的 249 人推断是无损的，多分类的 37 人不是。其中 11 人会被抬到更高的身份而不是领域：孔子变成士人，孟子和荀子变成学者，司马迁变成文臣。另外 89 人靠手写才躲开，例如白居易、杜甫的 `primary` 是 `poetry`，`rank` 会给他们 `official`。`categories` 被说成无序，但 `rank` 同为 2 的戏曲、小说、方术要靠数组顺序分胜负。

**2. 高 — 身份有三个写入者，泳道才是分组。** 登记是名义上的权威。`taxonomy/overrides/` 覆盖 331 人，其中司马炎、刘裕、朱元璋、吴三桂出现在两张表里。`apply-overrides.ts` 跨表时分类取并集，`primary` 取文件名字母序更靠前的那张表，不报冲突。

截至本次审查，这四人的 `primary` 没有冲突。朱元璋只是数组顺序不同。脚本使用 JSON 全等比较，下次执行 `--write` 仍会改写他。`infer-taxonomy.ts` 即使不加 `--write`，也会重写 `todo.json`。

泳道 id 是专题内的自由字符串，共有 38 种。`emperor` 复用了 8 次，`king`、`ruler` 和 `qin-ruler` 各自使用一套定义。`lane-map` 能对上分类的 519 个收录位中，有 110 个与人物的 `categories` 没有交集。唐专题还把李密放进 `chancellor`。

`founding`（40 人）和 `falling`（33 人）与官职、学科放在同一个无序数组中。朱元璋同时拥有这两个值。`src/ui` 不读取 `categories`、`primary` 和 `polity`。注释中的“按主分类配色”没有对应的渲染器。增加朝代会继续复制泳道，但不会自动得到跨专题身份。

**3. 高 — 拼音 id 加自由 note，已经把李泌接到李密身上。** `pipeline/registry/people/li-mi.json` 是隋末李密（582–619，`primary` 为 `rebel`，`polity` 为 `sui` 再 `tang`）。`pipeline/topics/tang/topic.json` 的关系是 `li-heng` → `li-mi`，note 为「肃宗倚李泌谋议，收复两京」。唐肃宗李亨是 711–762，与李密没有寿命重叠。lint 只检查 note 非空、两端 id 存在。全库另有 8 条双方生卒都齐全但并不重叠的关系，曾祖孙和身后师承是故意的，所以不能把「必须重叠」做成 error。校验看不见的是：note 里的人名不是 `target` 的 `name`、`display` 或 `aliases`。

**4. 中 — 分面词表没有产生筛选效果，且与人物分类使用不同定义。** `index.json` 的 `regions` 只有 `cn`，选中和「全部」都是 16 个专题。`themes` 只有 `dynasty`（15）和 `thought`（1）。16 个 `eras` 都有专题挂上，但除儒学跨三个时代、两晋再挂十六国外，基本上一时代一个专题。词表把西汉排在秦前面。专题 `range` 也不被要求对齐 `eras`：秦专题叙事到楚汉，era 只有 `qin`；汉代 `range` 收到公元 23，era 只有 `western-han`。思想主题停在「孔子到董仲舒」，理学分类却在宋元明清（程颢、程颐、朱熹、许衡、姚枢、王守仁等）。`search.json` 有 630 行，带了分类、政权和性别，搜索却只扫 `display`、`name`、`title`、`tags`。450 人有 `aliases`，别名不进索引。

**5. 中 — `polity` 不是干净的政权维，缺的 24 人不全是没词条。** 真没有词条的是虢、郐、申、许、褒、杞，共 12 人。`song-guo`（宋国）已经在词表里；宋哀公等 4 人的 tag 只有「宋」。`infer-taxonomy.ts` 故意不把裸「宋」映射成 `song`，以免西周宋国变成宋朝，于是留白。鲁、韩、晋的词条都在，孔子、孟子、荀子、子思、颜回、曾子、韩非、骊姬是没有对上 tag，不是缺词。21 个多值数组都顺着词表下标递增，看起来像时间先后，但词表把楚汉放在新莽之后，下标本身不能当纪年。词表还混了族群、民变军、北朝整块和合并的辽金；`wu-guo`、`zhongshan`、`chu-han`、`liao-jin`、`xiyu` 五条无人使用。385 人的 tags 仍写政权名，和 `polity` 双写。政权名字又不进目录，运行时只有裸 id。

**6. 中 — 纸面契约、体例和代码不是同一层。** `schema/` 三份都不被 `cli.ts` 读取。`person.schema.json` 没有 `categories`、`primary`、`polity`、`gender`，而且 `additionalProperties: false`。专题 schema 里的人物同样没有这些字段，关系 `note` 还是可选，lint 却把缺 note 当 error。`catalog.schema.json` 不承认 `categories`，同样拒绝额外字段，而生成的 `index.json` 含有 48 个分类，按这份 schema 是非法文件。真契约是 `src/types.ts` 和 `src/contract.ts`，v1 在不升版本号的情况下已经加了字段。`docs/设计方案.md` 第 3、6.5、10 节和 `pipeline/PLAYBOOK.md` 仍停在西周、春秋、战国、汉和儒学，并写着秦与东汉未做；工作区已有秦到清共 16 个专题。PLAYBOOK 的词表只写地区、朝代、主题。

**7. 低 — 草稿层有第二份生卒的位置，纪年槽也没有真正抽掉。** `cards/` 有 128 张西周卡，`status` 都是 `promoted`，YAML 生卒与登记 0 处不一致；另外 490 名登记人物没有卡。卡片 schema 允许自带年份，约定冲突时改卡、不改 JSON。`raw/` 是史料，不是名录。当前没有第二编译源，但卡片年份是潜在的平行事实。另外，数据里没有年份 0，刻度会跳过 0，线性比例尺仍给整数 0 留出一个年宽，享年用 `death - birth`，跨公元会多算一年。

## 建议

1. 把 `primary` 收成不变量：缺了就是 lint error，`compile.ts` 停止调用 `primaryOf`。`rank` 只留作目录排序，或删掉。249 名单分类的人可以把唯一分类抄进 `primary`；先人工处理那 37 名多分类的人，不要再靠 rank。
2. 分类只许改登记。`overrides/` 对齐之后改成只读校验（登记必须覆盖表里的集合和 `primary`），跨表 `primary` 不一致就失败，不要按文件名字母序取值。推断脚本的 dry-run 不要写 `todo.json`。
3. 给关系增加「note 若点名，必须命中 source/target 的 name、display 或 aliases」一类检查，或者把李泌登记成新 id，沿用 `ji-yijiu-jinghou` 的后缀，而不是复用 `li-mi`。不要把寿命重叠做成 error。
4. 分面按导航的真实能力收缩：只有中国时，不要让 `region` 看起来像筛选项；`eras` 按纪年重排，并让 `range` 里的政权能在词表里落点（五代、辽、金现在被 `liao-jin` 和缺失的时代词挡住）。`polities` 要么带 `name` 和序位进目录，并据此 lint 多值顺序，要么不要把裸 id 放进运行时。思想若要成为一个主题，就让它能挂到已有的理学人物，而不是只留一个停在董仲舒的专题。
5. 让 `schema/` 跟 `src/types.ts` 对齐，并在 `content:check` 里真校验；做不到就删掉 schema，避免两套契约。PLAYBOOK 补上职责边界：政权只进 `polity`，`tags` 留战役、著作和专名；`categories` 不存放 `founding` / `falling` 这种时段角色，时段放在专题泳道里。
