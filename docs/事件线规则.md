# 事件线规则（军事目录 / 历史事件目录）

> 状态：迁移治理规则（实体库尚未全面落地）。本文档是事件字段、收录和迁移的唯一口径；与 `pipeline/PLAYBOOK.md` 冲突时以本文档为准（PLAYBOOK 只保留事件入口的索引说明）。

### 0.1 Canonical source 与冻结边界

- 事件实体的目标唯一来源是 `content/events/<id>.md`。`public/data/events.json`、`military.json`、`history.json` 都是编译产物，不可手改。
- 迁移完成前，`pipeline/topics/*/topic.json` 内现有 `events[]` 是**冻结的旧 inline 输入**。
- 可以读取这些输入，也可以用它们生成迁移证据。
- 不得在这些输入中新增、删除、改名或补字段来绕过审核。
- 专题章节里的 `events` 引用暂不改写。改写必须属于一个有 manifest 对应项的迁移批次。
- 同一事件只允许一个 canonical id 和一个实体文件。专题出现只是 catalog 引用或旧输入来源，不是第二份实体。
- `pipeline/events-migration-manifest.json` 是迁移期间的 ledger；它记录旧来源、候选 canonical id、重复 alias 组、审核状态和逐条 gate。没有 manifest 条目的事件不得迁移。

### 0.2 候选、审核和 ledger 状态

每一条旧事件按以下顺序推进，状态只能向前，不得把已接受条目静默覆盖：

`frozen-inline` → `candidate` → `evidence-needed` / `rejected` → `approved` → `migrated` → `verified`

- `frozen-inline`：只存在旧专题输入，内容未被解释为 canonical 事实。
- `candidate`：确定了候选 id、type 和来源位置，但尚未完成资料核验。
- `evidence-needed`：缺年份锚点、出处或字段证据；要记录缺口，不编造资料。
- `rejected`：不满足收录闸门，保留理由和原始来源以便复核。
- `approved`：审核人确认字段、去重、taxonomy、catalog 归属和 sources；才可写入 `content/events/`。
- `migrated`：canonical Markdown 已创建，旧来源仍冻结，等待编译和逐条比对。
- `verified`：事件检查、编译产物、两个 catalog 视图和引用关系均通过 gate。

ledger 的每条记录至少包含以下字段：`legacyTopic`、`legacyId`、`legacyName`、`legacyYear`、`candidateId`、`aliases`、`status`、`duplicateGroup`、`evidence`、`review`、`gates`。

未决定的 `candidateId` 可以为 `null`。没有重复组时，`duplicateGroup` 可以为 `null`。`evidence` 只能引用现有资料或明确的待查位置。禁止用状态变更代替史料。

## 1. 三条内容线

站点有三条并列的内容线，共用同一套时间轴引擎，但组织维度不同：

| 线 | id | 组织维度 | 实体 |
|---|---|---|---|
| 人物 | `people` | 朝代专题（现有 17 个） | Person |
| 军事 | `military` | 纯时间（世纪分段） | 事件实体 `catalogs` 显式包含 `military`；缺省时兼容 `type: military` |
| 历史事件 | `history` | 纯时间（世纪分段） | 事件实体 `catalogs` 显式包含 `history`；缺省时兼容非军事或 `importance >= 2` |

军事与历史事件是**一套实体库的两个入口**，不是两套实体。赤壁之战只录一次，两个目录都能看到。

后两条不以朝代组织，因为改朝换代期的事件不属于任何单一朝代（野狐岭之战 1211 算金还是元，蒙金战争 1211–1234 横跨两个朝代）。

## 2. 事件实体

实体全局唯一，可被多个入口引用。存放于 `content/events/<id>.md`（与 `content/<topic>/` 并列）。

### 2.1 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一 kebab-case，见 2.2 |
| `status` | 否（新建必填 `draft`） | `draft` 不进入索引/上轴；审核完成后改为 `published`；缺省仅为存量兼容 |
| `name` | 是 | 事件全名，如「野狐岭之战」 |
| `display` | 否 | 轴上短标签。`name` 过长时必填（如「蒙金战争」→「蒙金」） |
| `type` | 是 | 类别，见 2.3 |
| `catalogs` | 否（新事件建议必填） | 目录视图：`military` / `history`；一个实体可同时进入两条目录，不改变 `type` |
| `scale` | 条件 | 军事规模，仅 `type: military` 时必填，见 2.4 |
| `importance` | 是 | `1` / `2` / `3`，见 2.5 |
| `year` | 是 | 起始年，公元前为负数；禁止写 `0`（不存在公元 0 年） |
| `yearAccuracy` | 是 | `exact` / `approx` / `disputed` / `unknown` |
| `yearNote` | 条件 | `approx` / `disputed` 必填（含 3.2 的夏商年份）；`exact` 可选 |
| `endYear` | 否 | 有则为 span，无则为 point |
| `endYearAccuracy` | 条件 | 有 `endYear` 时必填 |
| `endYearNote` | 条件 | `endYearAccuracy` 为 `approx` / `disputed` 时必填 |
| `place` | 条件 | 古地名。`type: military` 且 `scale ≠ war` 时必填 |
| `placeNow` | 否 | 今地，如「今河北张北」 |
| `belligerents` | 条件 | 交战方，`type: military` 时必填，≥ 2 个 polity id |
| `polity` | 条件 | 所属政权。非军事事件必填；军事事件用 `belligerents`，不填此字段 |
| `commanders` | 否 | 双方主将，见 2.6 |
| `people` | 否 | 相关人物 id（非主将的参与者、受影响者） |
| `result` | 否 | 一句话结果。军事事件建议填 |
| `parent` | 否 | 父事件 id，见 2.7 |
| `aliases` | 否 | 别名 |
| `tags` | 否 | 自由标签 |
| `sources` | 是 | ≥ 1 条，`work` 必填，见 2.8 |
| `desc` | 否 | 正文（Markdown body），事件经过与意义 |

`kind`（`point` / `span`）**不录入**，编译时由 `endYear` 是否存在推导，保持与 `src/types.ts` 的 `TimelineEvent` 兼容。

### 2.2 id 命名

`<专名主体>-<类名>`，全拼音 kebab-case，类名不加内部分隔：

```
duomen-zhibian       夺门之变
yehuling-zhizhan     野狐岭之战
chibi-zhizhan        赤壁之战
mengjin-zhanzheng    蒙金战争
daizexiang-qiyi      大泽乡起义
```

重名时加年份后缀：`xx-zhizhan-1211`。

**不带专题前缀**。现有内联事件的 `ming-duomen` 这类前缀 id 属于旧口径，迁移时去掉（见第 8 节）。

### 2.3 type

| type | 含义 | 例 |
|---|---|---|
| `military` | 军事 | 野狐岭之战、蒙金战争 |
| `political` | 政变 · 事变 | 夺门之变、沙丘之变、河阴之变 |
| `rebellion` | 起义 · 民变 | 大泽乡起义、黄巾之乱、安史之乱 |
| `institutional` | 制度 · 改革 | 商鞅变法、王安石变法、一条鞭法 |
| `diplomatic` | 盟约 · 和议 | 召陵之盟、澶渊之盟、绍兴和议 |
| `cultural` | 文化工程 | 永乐大典、郑和下西洋 |

`rebellion` 是事实分类。不得使用 `type` 隐式推导目录。

武装起义可以写 `catalogs: [military, history]`。非武装民变可以只写 `catalogs: [history]`。两者都保持 `type: rebellion`。

旧记录省略 `catalogs` 时，暂按旧规则兼容。新建和迁移记录必须显式声明 `catalogs`，避免把分类和目录混为一谈。

边界判定：**有交战双方且以军事行动为核心 → military；以权力更迭、制度、盟约为核心 → 其余各类**。靖难之役有大规模交战 → `military` + `tags: [政变]`；土木堡之变有交战 → `military`。

### 2.4 scale（仅军事）

| scale | 含义 | 形态 | 例 |
|---|---|---|---|
| `war` | 战争，跨年、含多场战役 | span | 汉匈战争、蒙金战争、明清战争 |
| `campaign` | 战役，有战略方向的一次用兵 | span 或 point | 河西之战、北伐 |
| `battle` | 会战，决定性交战 | point | 野狐岭、淝水、赤壁、官渡 |
| `engagement` | 战斗，小规模交锋 | point | 遭遇战、守城战 |

`war` 无 `place`（跨地域），`campaign` / `battle` / `engagement` 有 `place`。

### 2.5 importance

| 值 | 含义 | 表现 |
|---|---|---|
| `3` | 改变格局，通史必提 | 全目录可见，标签常显，驱动字号与避让优先级 |
| `2` | 重要，专题史必提 | 历史事件目录可见 |
| `1` | 有记录价值 | 仅军事目录可见 |

军事目录不看 `importance`，全量收录。

### 2.6 commanders

带 `side` 的结构化数组，`side` 取 `belligerents` 中的 polity id，可省略：

```yaml
commanders:
  - id: muqali
    side: menggu
  - id: wanyan-chengyu
    side: jin
```

扁平写法 `commanders: [muqali, wanyan-chengyu]` 亦合法，`side` 缺省时用 `desc` 说明归属。

### 2.7 parent 层级

只做两层：`war` → 其下 `campaign` / `battle`。**不允许三级嵌套**。

```
蒙金战争 (war, 1211–1234)
  ├─ 野狐岭之战 (battle, 1211)
  ├─ 中都之役 (battle, 1214)
  └─ 三峰山之战 (battle, 1232)
```

`parent` 可选——不是每场会战都有命名战争可归（柏举之战等）。渲染上父 `war` 画背景带，子事件 pin 落在带内。

### 2.8 sources

`work` 必填，`part` / `note` / `kind` 可选，`kind` 取值 `classic` / `modern` / `database`。

战役放宽：允许**单条主出处**即可，`kind: modern` 有效（《中国历代战争史》《中国军事通史》这类现代工具书可作主出处），不强求两条典籍互证。非军事事件建议两条，其中至少一条 `classic`。

## 3. 收录闸门

### 3.1 通用闸门（三条同时满足）

1. **年份锚点**：有确切或可考年份。无年份的不上轴
2. **格局改变**，满足任一：政权存亡/更替、疆域边界变动、内部权力结构重组、制度定型、主流叙事的转折点
3. **主流叙事在列**：通史、教科书、专题史会提到

### 3.2 军事类

- 收录下限到 `battle`（会战）
- `engagement`（战斗）**只在人物线有对应人物、且该战是其生平关键节点时**才收（李陵之战、睢阳保卫战）
- 时间起点**含夏，约 -2070**（与 `pipeline/vocab/dynasties.json` 的 `xia` 起点一致）。夏商纪年本身有争议，这些年份如实标 `approx` 或 `disputed`，并在 `yearNote` 说明所据（夏商周断代工程年表等）

### 3.3 非军事类

收录闸门同 3.1。典型不收：单一文献孤证的宫闱琐事、无制度后果的敕令、只见于地方志的灾异。

## 4. 目录组织

### 4.1 世纪分段

- 时间范围 **-2070 ~ 1949**（含夏商，止于民国结束。再往后越靠近当代，史料口径与叙事立场争议越大）
- 按世纪边界切段（前 11 世纪 = -1100 ~ -1001）
- **稀疏段自动合并**：段内事件数 < 3 时与相邻段合并，段名取首尾（如「前 16—前 11 世纪」）。夏商西周事件稀疏，会自动并成少数几段；宋元明清则按世纪细分
- 每段进入时**默认缩放适配该段密度**

### 4.2 朝代筛选

朝代不作为组织维度，只作为**可开关的筛选条件**。

实现方式：新增 `pipeline/vocab/dynasties.json`。字段为 `id`、`name`、`from` 和 `to`。

筛选条件是事件年份落在朝代区间内。需要补充 `xia`（夏）和 `shang`（商）两个词条。现有 `eras.json` 从西周起，不覆盖 -2070 至 -1046。

**这张表只用于筛选与分段标签，绝不用于推导事件归属。** 一个事件可以同时命中两个朝代区间（1211 年的野狐岭之战同时落在金与蒙古区间），这正是设计意图。

## 5. 与人物线的连接

- 事件 → 人物：`commanders`（主将）+ `people`（相关人），均为人物 id 引用
- 人物 → 事件：编译期反查，人物卡显示「参与的事件」列表（现有 `src/ui/card.ts` 的附属列表升级而来）
- 事件 → 事件：只通过 `parent` 表达战争—战役层级。**不建因果链**（夺门之变 ← 土木堡之变 这类先不做）
- 关系图 `src/ui/graph.ts` **一期不进事件节点**

## 6. 呈现规则

- 军事轴背景画**人物影子条**：由该段事件的 `commanders` / `people` 反查人物生命条，淡色低透明度绘制，保留「野狐岭之战落在成吉思汗红条旁边」的对照价值
- 每段影子条上限 12 条，按所关联事件的 `importance` 排序取前
- 数据显示阈值由 `scale` 驱动：默认画 `war`（背景带）/ `campaign` / `battle`（pin + 标签），`engagement` 画细线不显示标签，放大后才显形
- 密集区（三国、元末、明末）标签避让失败时下钻展开，与人物线的 `src/timeline/events.ts` 标签分行避让逻辑复用
- 事件卡：名称 / 时间 / 地点 / 交战方 / 结果 / 主将 / 相关人物 / 出处

### 8.1 重复 id、别名和 canonical 决策

- 先按 `(legacyTopic, legacyId)` 保留 258 条输入记录，再按名称、年份、人物和描述比对是否是同一事件。重复 id 或同名不自动合并。
- 认定同一事件时，选择一个不带专题前缀、符合 2.2 的 canonical id。
- 将其他旧 id 写入该实体的 `aliases`。
- 在 manifest 的 `duplicateGroup` 中保留全部来源。
- 证据不足时拆开保留，并标记为 `evidence-needed`。不能因为名称相似而合并事件。
- 当前盘点有 4 个重复 legacy id 和 6 组同名同年来源。其中 4 组相互重叠。
- manifest 按“重复 id 优先”记录 6 个 primary groups。不能把两个数字相加为 10 个独立问题。
- alias 只用于检索和迁移回溯，不得作为第二个实体文件或 catalog 项。一个 alias 不得指向两个 canonical id。
- 例如现有 `zhouyou`、`kongzi-zu`、`meng-liang`、`hanfei-qin` 在两个专题重复出现；它们先进入重复组，待逐条核对后才决定合并。`ming-duomen` 这类专题前缀 id 只提出去前缀候选，不视为已批准。

### 8.2 单条迁移验收门槛

一条记录只有同时满足以下条件，才能从 `migrated` 进入 `verified`：

1. manifest 中有唯一来源键和 canonical id，重复组、alias 和旧专题引用已记录。
2. 通过通用收录闸门；年份、accuracy、span 端点和 yearNote 与出处一致。
3. `type`、军事 `scale`、地点、政权/交战方、人物引用和 `parent` 均符合第 2 节；没有用朝代区间推导 `polity`。
4. `sources` 至少一条且可回溯到实际材料；非军事事件按 2.8 尽量有两条，其中至少一条 `classic`。缺证据则保持 `evidence-needed`。
5. canonical Markdown 只创建一份，旧 inline 记录没有被删除或改写；专题引用改写须在同一批次的 manifest 中可追踪。
6. `npm run events:check` 和 `npm run content:check` 必须通过。
7. 必须对生成的 `public/data/events.json`、`military.json` 和 `history.json` 做 source-to-output 比对。
8. 人物引用和 `parent` 引用必须解析。

批次验收还要报告：迁移条数、`evidence-needed`、`rejected`、重复组未决数、孤立人物引用和 catalog 计数变化。任何一项无法解释，批次保持未完成。

### 8.3 taxonomy 与 catalog 语义冻结

`type` 是事件事实分类。`scale` 是军事规模。`importance` 是历史叙事权重。三者不可互换，也不能由 catalog 反推。

`catalogs` 是显式目录投影。一个实体可以同时进入 `military` 和 `history`，但只能有一个 canonical 文件。

缺省 `catalogs` 的存量事件暂按兼容规则处理：`military` 收录 `type: military` 的事件；`history` 收录全部非军事事件和 `importance >= 2` 的军事事件。

catalog 过滤不会复制或改写实体字段。事件跨朝代时仍只保留一个 canonical 实体。`dynasties` 只表示年份区间命中标签，不能反向填入 `polity`，也不能证明政权归属。
