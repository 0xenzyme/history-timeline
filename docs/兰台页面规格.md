# 兰台页面规格

版本：M5 ｜ 日期：2026-11-08 ｜ 状态：完整群像阅读已实施；事件／作品真实内容样本待后续内容工作

本文把第一轮设计图转换为页面与交互契约。字段、关联和内容维护位置见《兰台数据规格》。视觉 token、组件尺寸和资产制作属于 M2 `DESIGN.md`，不在本文规定。

## 1. 首版范围

首版使用「页面模板」计数。九类设计模板全部保留；另增一个断代目录，解决主导航「断代」没有稳定落点的问题。运行时共有十类路由，不新增一套朝代实体。

| 模板 | 首版定位 | 实现依赖 |
| --- | --- | --- |
| 01 兰台首页 | 品牌、全站搜索和编辑推荐入口 | M4；M3 前先提供可用导航与搜索 |
| 02 年表 | 人物、事件和朝代共用时间坐标的核心工作区 | M3 |
| 03 列传目录 | 按时期和身份发现人物 | M4 |
| 04 人物详情 | 从个人进入事件、关系和群像 | M3 |
| 05 群像目录 | 按编辑主题发现系列 | M4 |
| 06 群像系列详情 | 阅读跨时代成员、关系与相关事件 | M5 |
| 07 纪事目录 | 检索和筛选统一事件实体库 | M4 |
| 08 事件详情 | 阅读事件事实、正文、人物与上下级 | M3 |
| 09 朝代总览 | 阅读时期背景并进入相关对象 | M4 |
| 10 断代目录 | 按时期进入朝代总览 | M4；M3 可先用同路由的简版 |

### 四项功能决策

| 功能 | 首版决策 | 页面表现与后续条件 |
| --- | --- | --- |
| 自动播放 | 不进入首版。 | 不显示按钮，不把「巡航」皮肤改称自动播放。后续需另定播放单位、速度、选中策略、暂停和结束行为。 |
| 代表作品 | 数据契约进入首版，按需显示。 | 人物详情和适用群像只在有核实作品时出现；没有独立作品实体、全文阅读或统一图片库。 |
| 个人经历年表 | 数据契约进入首版，按需显示。 | 使用人物自己的 `experiences`，与公共事件分区；没有经历时不显示空轴，不把 `bio` 自动拆成年份节点。 |
| 二度关系 | 不进入首版。 | 只显示当前人物或系列显式收录的一度关系；没有「展开二度关系」。后续先做跨专题关系去重和覆盖审计。 |

首版搜索覆盖人物、事件、群像和朝代。首版不包含账号、收藏、协作编辑、因果链、地图、世界史入口和作品全文。

## 2. 全站契约

### 2.1 路由和实体链接

新页面使用 path URL；静态托管需要把应用路径回退到 `index.html`。旧 hash 深链继续解析并重定向到等价新地址，不能回到无关默认页。

| 页面 | URL |
| --- | --- |
| 首页 | `/` |
| 年表 | `/timeline?topic=tang&view=tianbao&person=li-bai&from=710&to=770` |
| 列传目录 | `/people?dynasty=tang&category=poetry&sort=birth&page=1&view=grid` |
| 人物详情 | `/people/li-bai` |
| 群像目录 | `/collections?category=thought&page=1` |
| 群像系列详情 | `/collections/rujia-chuancheng?tab=relations` |
| 纪事目录 | `/events?dynasty=tang&type=rebellion&sort=year&page=1` |
| 事件详情 | `/events/anshi-zhiluan` |
| 断代目录 | `/eras` |
| 朝代总览 | `/eras/tang?tab=events` |
| 全站搜索 | `/search?q=李白&type=all` |

- 实体详情以 canonical id 为主键。同名、别名和旧 id 只用于检索和重定向。
- 目录把有效筛选、排序、页码、视图和查询写入 query；默认值可省略。
- 年表至少保存 `topic`、`view`、`from`、`to`、选中实体、内容线、人物分类、事件类型和显示的分类。缩放级别不必单独保存，由时间窗恢复。
- 详情页内 tab 写入 `tab`；普通滚动位置不写 URL。
- 非法 id 显示页面级未找到状态。非法筛选值被忽略并提示，不能产生空白页。
- 列传 `dynasty` 使用 topic id（例如 `tang`），不是 `dynasties.json` 的区间 id。纪事与朝代总览使用区间 id。
- 目录筛选和排序变化删除 `page`，由默认第 1 页开始；页码越界保留请求并显示有效页入口。

### 2.2 跳转与返回

1. 从列表、搜索或年表打开详情时使用 `pushState`，并保存来源 URL、结果滚动位置和年表选中状态。
2. 浏览器返回优先恢复原历史项。页面内的「返回」在有应用内来源时执行同一动作。
3. 直接打开详情或来源已不可用時，返回该实体的上级目录；年表详情回退到带实体定位的年表 URL。
4. 「在年表中查看」建立新年表历史项，并定位到对象。人物使用生卒年加可读边距；事件使用起止年加边距；群像使用成员范围；朝代使用 `from` / `to`。
5. 从详情继续打开另一实体时保留各自历史项。返回逐层恢复，不把所有跳转替换为同一历史项。
6. 分享链接只依赖 URL，不依赖内存中的来源状态。滚动恢复失败时保留对象、筛选和时间窗。

### 2.3 通用状态

- **加载**：保留页框和导航。目录使用结果占位；详情保留标题区占位；年表显示独立加载区，不能用默认人物或事件代替真实数据。
- **局部失败**：一个推荐、关系或关联模块失败时，其余模块可用；该模块显示「暂时无法加载」和重试。出处或核心实体失败时显示页面级错误。
- **空内容**：区分「没有结果」「尚未维护」「没有关联」和「加载失败」。筛选无结果时保留条件并提供重置；可选内容为空时隐藏模块，不显示连续空卡片。
- **未找到**：说明链接可能失效，提供全站搜索和上级目录，不自动跳到另一实体。
- **图片失败**：隐藏图片并使用姓名或首字占位。人物图、群像封面和朝代插画不得阻断正文。
- **搜索**：提交后进入统一结果页；输入框的即时建议可以取消。无结果显示查询词、清除条件和四个实体类型入口。

### 2.4 移动端与可用性

- 主导航收进菜单，当前栏目和全站搜索始终可达。
- 目录筛选进入底部面板；已选条件、结果数和重置留在正文。排序与视图切换保留，卡片默认单列。
- 详情按「身份与主操作 → 简介与年表 → 关系与相关对象 → 出处」排列。桌面侧栏不成为横向滚动区。
- 年表保持横向时间坐标，支持拖动和双指缩放。筛选和预览使用底部面板；底部朝代带保留为可收起控件。触屏没有 hover 才显示的信息。
- 系列关系图在窄屏切换为按中心人物排列的关系列表；显式提供图／列表切换，不能缩小到不可读。
- 所有主要操作可用键盘完成。焦点、文字标签、选中状态和错误提示不能只靠颜色。

## 3. 页面规格

以下每个模块都必须在《兰台数据规格》第 8 节有唯一数据映射。`按需`表示资料为空时隐藏，不影响其余页面。

### 01 兰台首页

**主要任务**：让读者选择搜索、年表、人物、群像、纪事或断代入口。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 品牌主视觉 | 固定品牌文案；「开始探索」进入默认年表 | 不铺完整年表；插画缺失不影响入口 |
| 全站搜索 | 查询四类实体，提交到 `/search` | 无结果行为见全站契约 |
| 四个栏目入口 | 年表、列传、群像、纪事 | 分别进入对应栏目，不带伪造筛选 |
| 推荐断代 | 编辑推荐朝代，最多首屏展示 5 个；「全部朝代」进入断代目录 | 点卡片进入朝代总览；未配置推荐时按目录顺序取有简介者 |
| 精选群像 | 编辑推荐系列、说明和代表人物 | 点卡片进入系列详情；尚无发布系列时隐藏整个模块 |
| 收束区 | 固定品牌文案和年表入口 | 不显示未经数据支持的内容数量 |

**移动端**：栏目入口双列或单列，推荐内容横向列表必须有明显滚动提示；搜索位于主按钮之前。  
**空／失败**：推荐失败不阻断导航与搜索；各推荐模块独立重试。

### 02 年表

**主要任务**：在同一时间基准比较人物生命线、事件、朝代和选定对象。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 专题／内容线与章节 | 选择人物专题、军事、历史事件或章节 | 更新数据与时间窗；保留可兼容的筛选，清理失效选中对象 |
| 分类面板 | 人物分类、事件类型和分类显隐 | 实时更新，URL 可分享；提供全选、清除和恢复章节默认 |
| 主时间轴 | 拖动、缩放、选择人物或事件；显示生卒与年份精度 | 点实体打开右侧预览；「查看详情」进入实体页；不自动播放 |
| 实体预览 | 核心身份、时间、简介、关系或相关人物摘要 | 数据缺失按字段隐藏；「查看详情」与「在年表中定位」不重复出现 |
| 朝代带 | 全时段导航、视窗框和朝代选择 | 点朝代进入对应总览；拖动视窗只改变时间窗 |
| 工具栏 | 缩放、重置、PNG／SVG 导出 | 导出使用当前时间窗和筛选；无自动播放控件 |

**返回**：从详情返回时恢复数据、筛选、时间窗、选中实体和预览。  
**移动端**：默认隐藏左右面板，选中实体后打开底部预览；筛选面板显示已选数量。  
**空／失败**：筛选无实体时显示空白时间坐标和重置入口；专题数据失败保留内容线导航并允许重试；导出失败不修改浏览状态。

### 03 列传目录

**主要任务**：按时期、身份和关键词发现人物。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 栏目标题与搜索 | 搜索姓名、display、aliases、title、tags 和 categories；事件关键词只在全局搜索使用 | 提交人物目录内查询；清除恢复全量 |
| 时期筛选 | 以专题编排为人物收录口径，不从生卒年推导 | 单选时期，支持清除；跨专题人物在每个相关专题可出现 |
| 身份筛选 | `categories` 多值交集，`primary` 不作为独立筛选 | 显示命中数；不提供性别筛选，除非后续另立产品需求 |
| 排序与视图 | 生年升／降序、编辑推荐；网格／列表 | 缺生年者排末并按 display 稳定排序；无「知名度」排序 |
| 人物结果 | 姓名、生卒及精度、title、bio、分类、polity、所属群像 | 整卡进入人物详情；群像 chip 可独立进入系列 |
| 分页 | 固定每页 24 人，筛选或排序变化回到第 1 页 | 页码越界显示空结果并提供回到有效页，不静默改查询 |

**移动端**：筛选底部面板，默认网格视图退化为单列列表。  
**空／失败**：无结果显示当前条件和重置；简介、分类、群像或图片缺失只隐藏对应字段。人物数据索引失败显示页面级重试。

### 04 人物详情

**主要任务**：理解一个人的身份、生平、公共事件、关系与群像归属。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 身份侧栏 | 姓名、生卒与 note、title、categories、polity、图片 | 字号和籍贯没有结构化字段，不展示虚构值；图片失败用姓名占位 |
| 主操作 | 「在年表中查看」 | 选择 canonical 人物所在专题并定位生命线 |
| 生平简介 | canonical `bio`，专题 overlay 只在对应专题语境使用 | 缺 bio 时显示「详细生平尚未整理」，不隐藏其他模块 |
| 个人经历 | `experiences` 按年份排序，区分确切、约略、异说和未知 | 按需；点出处展开来源；不与公共事件混写 |
| 时代事件 | 事件 `people` / `commanders` 反向引用，按年份排序 | 点条目进入事件详情；次生操作定位年表；李白与安史之乱无引用时不建立关联 |
| 代表作品 | `works` 的名称、年份、类型、说明和出处 | 按需；无全文、无默认图片，未知年份不推断 |
| 重要关系 | 合并同一对人物的一度关系，显示类型、方向、since 和 note | 点人物切换详情；无二度展开；跨专题去重规则见数据规格 |
| 所属群像 | 显式系列成员反查，显示系列名与成员说明 | 点卡片进入系列；无成员关系时隐藏 |
| 出处 | 人物 sources，经历和作品各自的 sources 就近显示 | database 明确标为线索，不作为年份证据 |

**移动端**：身份区后紧跟年表按钮，年表与关系转纵向列表。  
**空／失败**：`profile: brief` 仍提供可用身份页，不因缺 bio、关系、经历或作品而报错；核心人物不存在显示未找到；关联数据失败可独立重试。

### 05 群像目录

**主要任务**：按编辑主题发现经过策展的人物系列。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 栏目说明与搜索 | 搜索系列名称、aliases、summary、tags | 不直接以成员姓名冒充系列命中；成员查询走全站搜索 |
| 主题分类 | 使用受控 `category`，首版单选 | 分类没有系列时显示空结果，不自动推荐其他分类 |
| 排序 | 编辑推荐、名称；无人数和知名度排序 | 默认 `featuredOrder`，再按 id 稳定排序 |
| 系列卡片 | 名称、summary、category、代表成员、实际成员数、封面 | 整卡进入系列；成员数来自有效成员引用 |
| 分页 | 每页 12 个系列，筛选后回第 1 页 | 页码越界行为同列传 |

**移动端**：单列卡片，封面比例稳定且可隐藏。  
**空／失败**：没有已发布系列时显示栏目说明与「内容筹备中」，保留其他导航；人物或事件引用失效时编译阻断，不在页面静默扣除。

### 06 群像系列详情

**M5 实现边界**：`/collections/:id` 按 Collection 契约提供概览、成员、人物年表、显式关系、阅读路径和出处；相关纪事与作品视图仅在数据配置支持时出现。当前「儒家传承」真实样本只有前四类视图。事件／作品能力使用隔离测试 fixture 验收，不作为真实内容覆盖声明。

**主要任务**：解释成员为什么被放在一起，并提供跨时代阅读路径。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 系列头部 | 名称、策展导语、category、tags、封面、面包屑 | 面包屑分类用于目录筛选，不虚构层级实体 |
| 概览 | 正文、代表成员、编辑定义的探索路径 | 只引用已发布人物、事件和系列 tab |
| 代表人物 | 成员顺序、角色说明、生卒、人物入口 | `featured` 只影响推荐，不决定成员资格 |
| 人物年表 | 全部有效成员的生命线与时间精度 | 提供「在年表中查看」；不自动从系列生成新人物关系 |
| 师承／人物关系 | 系列显式关系引用，中心人物可切换 | 只显示引用的一度关系；无适用关系时不显示此 tab |
| 相关纪事 | 系列显式事件引用，按时间排序 | 进入事件详情；不从共同朝代或成员反查全部事件 |
| 作品 | 仅适用系列显示成员代表作品聚合 | 没有 `works` 时不显示；不提供作品全文 |

**首版 tab 规则**：`overview`、`members`、`timeline` 为必备；`relations`、`events`、`works` 由系列配置且数据非空时显示。默认 tab 必须真实可用。  
**移动端**：tab 可横向滚动，关系图默认列表；人物年表使用简化纵向年表并提供完整年表入口。  
**空／失败**：系列不存在显示未找到；可选 tab 失败不影响概览和成员；无效默认 tab 回退概览并替换 URL。

**M5 状态与恢复**：tab 使用 `tab`，关系成员使用 `member`，图／列表使用 `relation`。非法参数回退到本系列 `defaultView`，不写死为某个系列。完整年表入口使用全体成员年份范围及对应人物专题，不裁切到旧 `rujia` 范围。系列 tab 历史与「返回群像」入口分别保存；人物／事件详情返回后恢复系列 URL、选中对象与滚动位置。

### 07 纪事目录

**主要任务**：从统一事件实体库按时间、类型、地点和人物发现事件。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 事件搜索 | name、display、aliases、place、placeNow、关联人物姓名 | 军事和历史目录查询去重，同一实体只出现一次 |
| 朝代筛选 | 使用编译的 `dynasties` 区间命中，允许多朝代结果 | 不据此推导 polity；跨朝事件保留完整朝代标签 |
| 类型与目录筛选 | `type` 单选；military／history catalog 单选 | `catalogs` 决定目录，`type` 不代替目录 |
| 人物筛选 | 选择人物后匹配 `people` 与 `commanders` | 显示「尚无直接关联事件」而非按生卒年补全 |
| 排序与视图 | 起始年升／降序、importance；列表／卡片 | 同年按 importance 降序再按 id；重要性不是目录归属 |
| 事件结果 | 名称、起止年与精度、desc、地点、type、关联人物、importance | 整行进入事件详情；人物 chip 独立跳人物 |
| 分页 | 每页 20 条，筛选后回第 1 页 | 真实计数，页码越界行为同列传 |

**移动端**：默认列表；次要字段折叠到详情，筛入底部面板。  
**空／失败**：可选地点、人物、结果或图片缺失不显示占位图片；事件库失败显示页面级重试。

### 08 事件详情

**主要任务**：理解事件的时间、地点、经过、结果、人物和军事层级。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 事件头部 | name、起止年与精度 note、type、dynasties、一句话概述 | 概述取 `desc` 首段，不另写未经维护的宣传语 |
| 主操作 | 「在年表中查看」 | 选择事件所属的 history catalog 并定位完整跨度；可切 military |
| 事件概览与正文 | `desc` 作为首版完整叙事 | 不虚构「背景、经过、影响」分段；后续结构化写作另行立规 |
| 时间与地点 | year/endYear、place/placeNow、belligerents 或 polity | 缺地点显示「地点未记录」于信息区，不生成地图 |
| 结果与影响 | `result` | 缺省时隐藏该模块，不从正文自动抽取 |
| 事件年表 | 当前事件及时间范围；军事层级读取 `parent` / children，事件组成读取 `partOf` / components | 首版不自动聚合同时期事件；两种边分别展示，安史之乱保留 rebellion 类型 |
| 相关人物 | `commanders` 与 `people`，标注角色和 side | 同一人物合并展示多个角色；点人物进入详情 |
| 上级／组成事件 | parent 和 children 表达军事层级；partOf 和 components 表达组成 | 两类关系不混用，不表达因果；每项组成显示 note 和出处 |
| 相关群像 | 系列显式事件引用反查 | 无引用时隐藏，不按共同人物自动生成 |
| 出处 | 按 classic／modern／database 分组 | 保留原 work、part、note；database 标为线索 |

**移动端**：页内导航变为锚点下拉，人物和出处位于正文后。  
**空／失败**：事件正文、结果、地点、人物、parent 都可独立缺省；核心 id 不存在显示未找到；关联失败允许正文继续阅读。

### 09 朝代总览

**主要任务**：阅读一个时期的基本背景，并进入年表、人物、事件和群像。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 朝代头部 | name、from/to、国祚、编辑概述、封面 | 国祚按 `to - from` 显示约数；跨年不声称精确周年；区间争议在 note 展示 |
| 基本信息 | 都城、建立者等显式资料 | 每项可空并就近带来源；不从 polity 或首个人物推导建立者 |
| 页内视图 | 概览、朝代年表、关键人物、重要事件、相关群像 | tab 可分享；无相关群像时隐藏对应 tab |
| 朝代年表 | 显式精选事件按时间排列，点事件进入详情 | 不提供完整缩放和平移；「查看完整年表」进入年表 |
| 关键人物 | 编辑 `featuredPeople` | 无推荐时按专题顺序取前 6 人，不称「最重要」；进人物详情 |
| 重要事件 | 编辑 `featuredEvents` | 无推荐时按 importance、时间取前 6 个区间命中事件；进事件详情 |
| 时代气质 | 编辑正文或要点 | 无维护内容时隐藏，不自动拼接标签 |
| 相关群像 | 显式 dynasty 引用反查 | 进入系列详情 |
| 主操作 | 「查看本朝年表」 | 有对应人物专题则定位专题和朝代区间；无专题时进入 history 时间窗 |

**移动端**：首屏压缩为基本身份与主操作，年表为纵向节点。  
**空／失败**：朝代只有区间时仍显示可用总览，概述、都城、建立者和推荐按需隐藏；画像与插画可失败；核心朝代 id 不存在显示未找到。

### 10 断代目录

**主要任务**：提供「断代」导航的稳定入口，并说明时期可重叠。

| 模块 | 内容与操作 | 状态与跳转 |
| --- | --- | --- |
| 栏目说明 | 「按时期浏览朝代、关键人物和重要事件」 | 不宣称各朝代是互斥年代树 |
| 时期搜索 | 按朝代 name、aliases 搜索 | 无结果提供清除，不跳到相近朝代 |
| 时期分组 | 先秦、秦汉、魏晋南北朝、隋唐五代、宋辽金元、明清、民国为展示分组 | 分组来自编辑配置，不改写 dynasty 自身区间 |
| 朝代卡片 | name、from/to、概述摘要、关键人物与事件计数 | 进入朝代总览；计数来自实际关联，重叠事件可在多张卡计数 |
| 年表入口 | 「在时间轴中查看全部」 | 进入 history 全时段年表 |

**移动端**：按分组纵向排列，不使用需要横向滚动的时间轴。  
**空／失败**：无概述或计数为 0 不隐藏真实朝代；计数模块失败时保留朝代入口并隐藏计数。

## 5. M1.5 决策与后续依赖

### 已进入 M2 的确定输入

1. M2 为十类路由设计九类既有模板和断代目录；共用目录基础组件，保留年表和关系视图差异。
2. 首版无自动播放和二度关系；M2 不为它们预留可见控件。
3. 作品、个人经历、关系、群像和推荐都使用按需模块；M2 必须设计模块隐藏后的连续排版。
4. M2 必须覆盖目录、详情、年表、关系列表的移动端状态，以及加载、空内容、局部失败、未找到和图片失败。
5. 详情与年表跳转使用可分享 URL 和历史恢复；M2 不另建只有视觉意义的返回按钮。

### 不阻塞 M2 的内容与实现依赖

- M3 前：实现新路由与数据读取层；保留旧 hash；完成唐代、李白、安史之乱核心路径。李白与安史之乱是否补直接引用属于内容校订，不是 M3 的必要前提。
- M3／M4 前：M1.5 已提供人物 sources、aliases、可选 experiences/works 的详情读取；事件 children 与 components 由不同事实字段派生，页面分别消费。
- M4 前：建立 DynastyProfile 与编辑推荐，完成断代目录、全站搜索和目录分页。
- M5 前：M1.5 已提供 Collection canonical 文件、维护入口、编译和读取；儒家传承样本含朱熹，未引用既有跨代师承边。
- 后续另立需求：自动播放、二度关系、事件长叙事结构、作品全文、地图与素材批量生产。

M1.5 不要求产品方向变更。M2 基础视觉可并行；人物经历、事件组成与群像数据组件定稿依赖本阶段验收，M3 同时依赖 M2。
