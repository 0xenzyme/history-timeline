# 内容质量与告警口径

本文说明公开协作时的内容质量边界。它不替代 [内容编写手册](../pipeline/PLAYBOOK.md) 和 [事件线规则](事件线规则.md)。

## 发布基线

2026-11-02 的开源准备检查中，`npm run build` 通过，内容校验没有 error，但留下 406 条 warning。warning 是人工复核入口，不等同于 406 个已确认史实错误。

| 类型 | 基线数量 | 当前处理口径 |
| --- | ---: | --- |
| `EVENT_PERSON_POLITY` | 142 | 包含规则判据冲突、政权兴起期、多政权归属等情况。先统一规则，再逐条修改确有错误的数据。 |
| `EVENT_PERSON_DATE` | 9 | 包含过程事件只锚终点、人物卒年作为可见年份等口径。按事件时间规则逐条复核。 |
| 非军事事件建议两条出处 | 122 | 属于证据完善建议。优先补核心条目，不为凑数添加低质量出处。 |
| 军事事件缺少 `result` | 80 | 属于字段完整性待办。只在有出处支持时补结果。 |
| 长名称缺少 `display` | 40 | 属于轴上展示优化。补充简短且不改变原意的显示名。 |
| 专题详表关系待补 | 11 个专题 | 属于内容扩写待办。关系必须有实际语义和说明。 |

数量是当前基线，不作为长期目标。后续贡献以“不新增由本次改动引起的 warning”为基本要求。

## 不在开源准备中批量修改的内容

- 不根据人物生卒年自动推断 `polity`。
- 不把兴起期、伞形政权或跨政权人物强行改成单一归属。
- 不为消除日期告警而虚构起止年或提高年份精度。
- 不为满足双出处建议而复制不可核查的网页结论。
- 不为补齐关系或 `result` 而编写没有史料支持的说明。

## 第三方来源

部分条目目前把百度百科或维基百科列为参考出处。第三方百科可以帮助定位线索，但不应替代典籍或现代研究。后续校订应优先补充可核查的原始出处。

项目许可证只覆盖独立撰写的原创文案和结构化内容。古籍原文及第三方材料仍保持各自权利状态，详见 [原创内容许可](../LICENSE-CONTENT.md)。

## 公开协作流程

1. 使用内容订正 Issue 指明实体、问题和出处。
2. 维护者先判断是数据错误、规则冲突还是完整性建议。
3. 数据修改必须回到该实体的 canonical 源文件。
4. 修改后运行相应内容校验和 `npm run build`。
5. 若判据本身错误，修改校验规则并说明原因，不批量扭曲内容来适应判据。
