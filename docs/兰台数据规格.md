# 兰台数据规格

版本：M4 ｜ 日期：2026-11-07 ｜ 状态：内容发现数据链路已实施

本文定义页面模块的数据来源、扩展字段、canonical 维护位置、关联规则和缺省处理。页面行为见《兰台页面规格》。M1.5 将人物详情、Collection 和事件组合接入最小生产链路；页面实现仍属后续阶段。

## 1. 不变量与现状

1. 人物唯一事实来源仍为 `content/<topic>/<id>.md`；44 条未迁移记录仍为 `pipeline/registry/people/<id>.json`。同一人不得新增第二份文件。
2. 事件唯一事实来源仍为 `content/events/<id>.md`。military 与 history 是同一事件库的两个 catalog，不是两套实体。
3. 专题编排、关系和章节仍位于 `pipeline/topics/<id>/topic.json`。冻结的旧 inline `events[]` 不作为新功能的内容来源。
4. `public/data/` 只由 pipeline 生成。前端只经 `src/types.ts`、`src/contract.ts`、`src/loader.ts` 和路由／数据读取层访问。
5. 人物 `polity`、事件 `polity` / `belligerents` 与朝代区间是不同语义。不得从生卒年或 `dynasties` 推导人物、事件归属。
6. `catalogs` 决定事件目录成员；`importance` 只决定展示优先级；`parent` 只表达两层军事层级；`partOf` 只表达有出处和说明的事件组成；`relations` 只表达有 note 的一度人物关系。
7. 年份和精度必须原样保留。约略、异说、未知不得为了提高页面完整度而改写。

## 2. 数据分层与编译边界

| 层 | 内容 | 首版处理 |
| --- | --- | --- |
| 人物事实 | 身份、生卒、bio、aliases、sources、作品、个人经历 | 扩展人物 canonical 文件；专题 overlay 不覆盖这些事实 |
| 事件事实 | 时间、类型、地点、人物、结果、军事层级、事件组成、正文、sources | 保留 parent；新增成员侧 partOf；children 与 components 均为派生索引 |
| 专题编排 | lane、专题文案、章节、既有关系 | 保留；专题不是群像或朝代实体 |
| 群像策展 | Collection、成员、代表成员、关系与事件引用、探索路径 | 新建独立 canonical 文件和编译器 |
| 朝代资料 | DynastyProfile、基本信息、推荐与展示分组 | 新建独立 canonical 文件；`vocab/dynasties.json` 仍只存区间 |
| 编辑配置 | 首页推荐、断代展示分组、目录默认排序 | 使用受控配置文件，不散落在 UI |
| 派生索引 | 人物—事件反查、系列成员反查、children、components、计数、搜索 | pipeline 生成；不得反向写成事实字段 |

`topic`、`Collection` 与 `DynastyProfile` 不互相替代。一个 Collection 可以跨多个 topic 和 dynasty；一个 DynastyProfile 可以引用多个 topic，但没有 topic 也可发布。

## 3. 现有字段映射

### 3.1 Person、Topic 与 Relation

| --- | --- | --- |
| 姓名与短名 | `Person.name` / `display` | display 用于卡片和轴，name 用于详情全名；搜索同时匹配 aliases |

| 叙事归属 | polity | 只翻译词表并链接相关时期；不能按生卒年推导 |
| 专题与章节 | Topic.meta、lanes、views、people overlay | 年表继续使用；跨专题显示保留 overlay 语境 |
| 人物关系 | Topic.relationTypes、relations | source/target/type/note/since；首版只展开当前人物一度边 |
| 人物—事件 | EventRecord.people、commanders | pipeline 建反向索引；commander 与 people 角色可合并，不能按生卒重叠补边 |

| 人物搜索 | name、display、aliases、title、tags、categories | 字号只有录入 aliases 才参与搜索；不能从 bio 提取 |

### 3.2 EventRecord

| 页面用途 | 来源字段 | 规则与缺省 |
| --- | --- | --- |
| 名称与正文 | name、display、desc | 首版 desc 是完整叙事，不虚构背景／经过／影响分段 |
| 时间 | year/endYear、Accuracy、Note | `kind` 由 endYear 推导；年表定位完整跨度 |
| 类型与目录 | type、catalogs、scale | type 过滤事实类型；catalogs 过滤目录；scale 仅军事显示 |
| 展示优先级 | importance | 可排序和强调，不决定收录、相关性或知名度 |
| 朝代标签 | dynasties | 由区间命中，可重叠；不回填 polity |
| 政权与交战方 | polity、belligerents、commanders.side | 按事件语义显示，不与人物 polity 强行相等 |
| 地点 | place、placeNow | 缺省隐藏地点行；首版无地图 |
| 人物 | people、commanders | 去重后保留角色；建立人物反向链接 |
| 结果 | result | 缺省隐藏模块，不从 desc 截取结果 |
| 军事层级 | parent | pipeline 反查 children；只显示上下级，不生成相关战争或因果链 |
| 事件组成 | `partOf: Array<{ id, note, sources }>` | 子事件指向组合事件；只读 `events/<id>.json` 的 `components` 反查；不是 parent、因果或相关推荐 |
| 事件—群像 | Collection.events | pipeline 反查；共同人物或朝代不自动产生群像关联 |
| 搜索 | name、display、aliases、place、placeNow、关联人物姓名 | 双 catalog 合并为一个实体结果 |
| 出处 | sources | 显示 work/part/note/kind；database 标为线索 |

## 4. 首版扩展契约

以下为扩展契约。字段未维护时省略；不在 Markdown 中写「待填」占位内容发布。M1.5 的可选数组在 canonical 与运行时均省略，不写空数组。

### 4.1 PersonDetail 扩展

在现有 RegistryPerson 上增加四个可选字段；`sources` 和 `aliases` 是已有源字段，只需进入运行时详情。

| 字段 | 结构 | 维护位置与规则 |
| --- | --- | --- |
| `aliases` | `string[]` | 沿用现有人物 canonical 文件；加入 people detail 与搜索，不是独立实体 |
| `sources` | `SourceRef[]` | 沿用现有人物 canonical 文件；进入人物详情运行时，废除「人物出处不进入运行时」的旧前端限制 |
| `works` | `PersonWork[]` | 人物 canonical frontmatter；只收有来源支持的代表作品 |
| `experiences` | `PersonExperience[]` | 人物 canonical frontmatter；只收有来源支持的个人节点，不写入公共事件库 |

```ts
interface PersonWork {
  id: string;
  title: string;
  kind?: 'poetry' | 'prose' | 'calligraphy' | 'painting' | 'music' | 'book' | 'other';
  year?: number;
  yearAccuracy?: Accuracy;
  yearNote?: string;
  note?: string;
  sources: SourceRef[];
}

interface PersonExperience {
  id: string;
  label: string;
  year?: number;
  yearAccuracy: Accuracy;
  yearNote?: string;
  endYear?: number;
  endYearAccuracy?: Accuracy;
  endYearNote?: string;
  place?: string;
  note: string;
  sources: SourceRef[];
}
```

- `id` 只需在人物内唯一，使用 kebab-case。作品和个人节点不是全站独立实体，不生成详情 URL。
- `yearAccuracy: approx | disputed` 必须有 note；`unknown` 可省略 year，并在详情「年份待考」分组显示。
- experiences 的 endYear 不得早于 year；place 只是个人行迹，不替代事件地点。
- 代表作品不默认包含全文、图片和确定创作年。作品出现在 bio 中不等于已录入 works。
- 若一项经历同时满足公共事件收录闸门，可以在事件库另有 canonical 事件；两边各自叙述，通过人物—事件引用连接，不自动同步文字。
- `PersonExperience` 可增加 `event?: string`。存在时，个人节点只保留自己的标签、note 与 sources，公共时间、地点与参与事实读取所引用事件；不得在两处重复维护这些字段。
- 44 条 legacy JSON 可以读取这些扩展，但只有完成现有迁移条件后才改存储形式。

### 4.2 事件组合 partOf

决策与替代方案见 [M1.5 事件组合与详情数据决策](decisions/m1-5-event-composition.md)。`parent` 的规则完全不变。

```ts
interface EventPartRef {
  id: string;
  note: string;
  sources: SourceRef[];
}
```

- 成员事件写 `partOf`，组合事件的 `components` 仅由编译器生成。每项必须有组成说明与出处，不能只靠共同人物或共享年代。
- 组合只能是有 `endYear` 的 `rebellion`，或 `scale: war | campaign` 的军事事件。成员可以是 point、普通 span 或符合相同类型约束的组合；允许多层组合链但不允许自引用或循环。
- 成员与组合的时间区间必须相交。组合不要求覆盖成员的完整时间，但不能把完全处于区间外的事件写成组成。
- 同一成员对同一组合只允许一条；空 `partOf`、重复 `sources`、缺失引用或 draft 引用均拒绝进入发布产物。删除或取消发布会保留错误，不静默删边。
- `partOf` 不改变 `type`、`catalogs`、`importance`、`parent` 或 `children`，不自动增加成员或组合到另一目录。

### 4.3 Collection

群像是独立策展实体，不是 tags 的自动集合，也不是 `topic.json` 的别名。

**canonical 位置**：`content/collections/<id>.md`  
**生成索引**：`content/collections.md`，由 `collections:format` 生成，不手改。  
**骨架**：`content/_template-collection.md`。  
**分类词表**：`pipeline/vocab/collection-categories.json`。  
**结构校验**：`pipeline/schema/collection.schema.json` 和对应 lint。  
**运行时产物**：`public/data/collections.json`（目录瘦索引）与 `public/data/collections/<id>.json`（详情）。

```ts
interface Collection {
  id: string;
  status: 'draft' | 'published';
  name: string;
  aliases?: string[];
  category: string;
  summary: string;
  body?: string;
  tags?: string[];
  featuredOrder?: number;
  cover?: MediaRef;
  members: CollectionMember[];
  relations?: CollectionRelationRef[];
  events?: string[];
  dynasties?: string[];
  views: Array<'overview' | 'members' | 'timeline' | 'relations' | 'events' | 'works'>;
  defaultView: 'overview' | 'members' | 'timeline' | 'relations' | 'events' | 'works';
  path?: CollectionStep[];
  sources: SourceRef[];
}

interface CollectionMember {
  id: string;
  order: number;
  featured?: boolean;
  role?: string;
}

interface CollectionRelationRef {
  source: string;
  target: string;
  type: string;
}

interface CollectionStep {
  label: string;
  person?: string;
  event?: string;
  view?: Collection['defaultView'];
}
```

- members 至少 2 人；id 必须解析到唯一人物。order 是编辑阅读顺序，不代表师承或年代。
- relations 的 `(source,target,type)` 必须能在某个已发布 topic 的关系中解析，且 source/target 都是该系列成员。note 和方向沿用原关系，不另写第二份事实。
- 若史料需要一条现有专题没有的关系，应先在合适 topic 按人物规则维护，再由 Collection 引用。不得把系列文件变成关系事实的旁路。
- events 和 dynasties 都是显式引用；编译器只反查链接，不扩充成员。
- views 只列真实可用视图。relations 需要至少一条关系，events 需要至少一个事件，works 需要至少一个成员有作品。
- defaultView 必须在 views 中。`path` 的每一步至多一个 person 或 event，view 必须属于本系列。
- Collection.sources 支撑策展说明和成员范围；成员事实仍由人物 sources 支撑，事件事实仍由事件 sources 支撑。
- draft 不进入目录、搜索、人物所属群像和朝代相关群像。

**儒家传承要求**：新建 `rujia-chuancheng` 时，成员可跨 `chunqiu`、`zhanguo`、`han`、`song` 等 topic；不得直接复用 `rujia` 专题的 `range: [-560,-90]`。朱熹 `zhu-xi` 只有显式加入 members 才出现；与二程的关系只有先形成可引用的 relation 才显示。

### 4.4 DynastyProfile

**区间来源**：`pipeline/vocab/dynasties.json`，继续只保存 `id/name/from/to`。  
**策展资料**：`pipeline/dynasties/<id>.json`，与区间 id 一一对应。  
**结构校验**：`pipeline/schema/dynasty-profile.schema.json`。  
**运行时产物**：`public/data/eras.json`（目录与搜索）和 `public/data/eras/<id>.json`（详情）。

```ts
interface DynastyProfile {
  id: string;
  aliases?: string[];
  summary?: string;
  body?: string;
  note?: string;
  capitals?: Array<{ name: string; note?: string }>;
  founders?: Array<{ id: string; note?: string }>;
  topics?: string[];
  group: 'pre-qin' | 'qin-han' | 'weijin-nanbei' | 'sui-tang-wudai' | 'song-liao-jin-yuan' | 'ming-qing' | 'minguo';
  featuredPeople?: string[];
  featuredEvents?: string[];
  collections?: string[];
  cover?: MediaRef;
  sources: SourceRef[];
}
```

- summary、capitals、founders 和 body 都按需维护。founders.id 必须解析人物，不由最早人物或 polity 推断。
- topics 是年表入口推荐，不改变人物 canonical topic 或 polity。
- featuredPeople 必须在该朝代对应 topic 或有明确编辑理由；featuredEvents 必须在事件的 dynasties 中命中该朝代。
- collections 是显式相关群像；也可由 Collection.dynasties 反查。两边同时出现时按 id 去重。
- group 只服务断代目录展示，不是层级朝代树，不覆盖可重叠的 from/to。
- sources 支撑资料与区间说明。没有 profile 时，仍可使用 vocab 区间生成基本朝代卡；详情显示「时代资料尚未整理」。

### 4.5 编辑推荐与媒体

**维护位置**：`pipeline/editorial/home.json`。  
**运行时产物**：并入 `public/data/index.json` 的 `editorial` 字段。

```ts
interface HomeEditorial {
  dynasties: string[];
  collections: string[];
}

interface MediaRef {
  src: string;
  alt: string;
  credit?: string;
  license?: string;
}
```

- 推荐只引用 published Collection 和已知 dynasty；featuredOrder 决定默认顺序。
- 缺省时首页推荐 dynasty 取有 summary 的前 5 项；没有发布 Collection 时隐藏精选群像。
- 图片放在 `public/media/people/`、`public/media/collections/`、`public/media/eras/`。MediaRef 只保存已确认可用资产。
- 人物 canonical 数据目前没有 `image` 字段。人物详情仅以约定路径探测可选本地图片，失败保留姓名占位，不把该路径反写为人物事实。
- 图片路径失败或无版权信息时不阻碍正文。设计稿图片和 `temp/` 资产不自动进入正式数据。

## 5. 运行时产物与派生规则

| 产物 | 内容 | 使用页面 |
| --- | --- | --- |
| `index.json` | 现有 topics、lines、vocab；新增 eras、collections 和 editorial 瘦索引 | 全站导航、首页、搜索 |
| `people.json` | 跨专题人物瘦索引，增加 aliases 和 bio 摘要；保留 topicId/topicTitle | 列传、全局搜索、关联卡 |
| `people/<id>.json` | 唯一 PersonDetail、topics、关系、经历、作品、sources | 人物详情；避免为一个人加载所有专题 |
| `<topic>.json` | 现有专题年表数据 | 年表、章节 |
| `military.json` / `history.json` | 同一事件库的两个目录视图 | 年表、纪事 |
| `events/<id>.json` | 唯一事件、children 与 components 派生索引、关联人物瘦卡 | 事件详情；不必同时加载两个事件目录 |
| `collections.json` | published Collection 目录行、代表成员和成员数 | 群像目录、首页、搜索 |
| `collections/<id>.json` | 完整策展、成员卡、关系、事件卡、可用视图 | 系列详情 |
| `eras.json` | dynasty 区间、profile 摘要、group、推荐计数 | 断代目录、搜索 |
| `eras/<id>.json` | 朝代资料、推荐人物、事件、群像和年表入口 | 朝代总览 |

实现时可以在首版合并小型详情产物，但语义和唯一来源不变。不得让 renderer 直接读取 content 或 pipeline。

所有新详情与 Collection 产物使用 `contractVersion: 1`；新增字段可选。旧事件线、人物索引和专题没有新增字段时继续通过运行时校验，不批量迁移现有实体。

### 派生索引规则

1. 人物—事件：合并 `people` 和 `commanders[].id`，按 event id 去重；同一人的 commander 角色优先标注，其他相关角色保留。
2. 事件 children：由所有 `parent` 反查，按 year、importance、id 排序；编译时检查 parent 存在且不构成三级层级。`components` 另由 `partOf` 反查，二者不合并。
3. 人物—群像：由 published Collection.members 反查，按 featuredOrder、id 排序。
4. 事件—群像：由 published Collection.events 反查，不从成员的共同事件生成。
5. 朝代—群像：合并 DynastyProfile.collections 与 Collection.dynasties，按 id 去重。
6. 年表范围：Collection 取所有具有年份的成员最小 birth 至最大 death，再加可读边距；无有效范围时禁用年表主操作并说明原因。
7. 朝代计数：人物按对应 topic 有效 id 去重，事件按 dynasties 命中去重；同事件可在多个朝代计数。
8. 搜索：四类实体分别命中后合并，精确 name/display/alias 优先，其后为其他字段；同分按 id。没有知名度权重。

## 6. 关系去重与跨专题处理

首版使用同一对人物的一度关系。关系主键为：

`source + target + type`。

- directed=false 的关系把 source/target 按 id 排序后形成主键；directed=true 保留方向。
- 同主键出现在多个专题时，合并所有非空 note 和 since；note 完全相同只显示一次，不同则并列显示。
- 同主键的 `directed` 不一致时编译失败，因为无法确定主键与方向。显示名称、颜色或 dash 不一致时保留来源 topic 的定义并产生 warning；不得全局静默覆盖。两个不同的已知 `since` 产生 `[RELATION_CONFLICT]` warning，Collection 不得引用该边；仅一方缺省时保留已知值并列为后续校订项。
- 不同 type 的多条关系可以共存。series 只显示其 relations 显式引用的边。
- 首版不计算朋友的朋友、不递归扩展、不把共同事件或生卒重叠转换为关系。
- 人物详情可以选择合并全部专题的一度关系；年表仍按当前专题显示，避免跨专题引入未加载节点。

## 7. 缺省、错误与校验

| 情况 | 数据／编译处理 | 页面处理 |
| --- | --- | --- |
| brief 人物无 bio | 合法 | 显示「详细生平尚未整理」，其余可用 |
| 无 works / experiences | 合法，字段省略 | 隐藏对应模块或 tab |
| 无关系 / 群像 / 相关事件 | 合法 | 显示无关联或隐藏，不生成推断关系 |
| 事件无 place / result / people | 合法 | 隐藏可选模块 |
| 年份 approx / disputed | 必须有对应 note | 显示精度和 note |
| 年份 unknown | year 可空 | 不进入可定位年表节点；放入年份待考 |
| Collection 引用不存在的人物 | 编译 error | 不发布该详情，不能静默删人；人物没有独立 draft 状态，brief 与 legacy 可以入组 |
| DynastyProfile 推荐不存在或事件不在区间 | 编译 error | 不展示错误推荐 |
| 重复 canonical id / 多份事实文件 | 编译 error | 阻断发布 |
| 局部运行时 JSON 请求失败 | 保留已成功数据 | 模块重试，不抹掉整页 |
| 核心实体或 id 未找到 | 返回明确 not-found | 不回退到默认实体 |

新增内容必须通过对应 Markdown／JSON schema、引用检查和 `npm run content:check`。页面模块为空不是绕过校验的理由。

## 9. 搜索、筛选与排序细则

- 全站搜索索引使用实体 kind 区分 person、event、collection、dynasty；同一实体跨 topic 或 catalog 只返回一次，并携带可用入口列表。
- 人物目录内的「时期」按 topic 编排，不按 polity 或生卒年。UI 标签使用「所属时期」，说明中明确跨专题人物可重复出现。
- 纪事目录内的「朝代」按 dynasties 区间命中。一个事件可以命中多个筛选，但在合并结果中只显示一次。
- 地点查询匹配 place/placeNow；人物查询同时匹配 people 和 commanders。查无结果不代表人物未经历某事，只代表尚无结构化直接引用。
- 作品、经历和关系的全文不进入首版全局搜索索引，避免无法解释的命中；后续需要时另定权重。
- 目录默认排序只使用可解释字段。birth/year 升序、importance、featuredOrder 和 id 均可使用；不使用虚构知名度。

- 安史之乱：`content/events/anshi-zhiluan.md` 有 755–763、8 位 people、result 和两条 classic sources，但无 `li-bai`。首版走查必须确认两边都不生成李白直接关联。
- 安史之战节点：M1.5 为香积寺之战和睢阳保卫战增加有出处的 `partOf: anshi-zhiluan`。它们不写入 parent，也不成为军事 children；安史之乱保留 rebellion 类型。

### 儒家传承

- 现有 `pipeline/topics/rujia/topic.json` 不是完整跨时代 Collection。它只覆盖至西汉，members 中没有朱熹。
- 孔子、孟子、朱熹均可由 people 索引唯一解析，分别保留 disputed、approx、exact 精度。
