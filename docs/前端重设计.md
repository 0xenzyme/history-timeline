## 二、前端现状盘点

### 2.1 已经能跑的功能

1. 三条内容线切换：人物 / 军事 / 历史事件（`index.html:24`、`src/app/app.ts:1162`）。
2. 人物线：泳道分组、生卒条四种可信度画法（精确实色 / 约略虚线 / 异说密虚线 / 生卒缺失端点渐隐，`src/app/app.ts:509`）、选中人物后关系曲线直接画在轴上（`src/app/app.ts:619`）、章节镜头（`src/app/app.ts:1448`）。
3. 事件线：按 `type` 分行（`src/app/layout.ts:114`）、`kind` 决定点或段、点标记大小跟 `importance`（`src/app/app.ts:434`）。
4. 人物线与事件同框：全量事件的段事件画成贯穿绘图区的背景带（`src/app/app.ts:323`）；「事件条」展开后事件点进入头部条带，按像素距离聚合计数、可点，命中测试与绘制同一口径（`src/app/app.ts:760`、`src/app/app.ts:1019`）。
5. 底部朝代带承担总览：26 个朝代按区间着色、240 桶事件密度、可拖动可拉伸的视窗框，点朝代跳到重叠最多的专题（`src/app/app.ts:872`、`src/app/app.ts:1684`、`src/app/model.ts:131`）。吸顶年轴同样画朝代色块与年份刻度（`src/app/app.ts:673`）。
6. 搜索：一次查全量，不做"专题内优先再落全局"两段式；人物匹配姓名 / display / 标签，事件匹配姓名 / display / 别名，人物在前事件在后，命中即跳转（`src/app/app.ts:1342`）。
7. 卡片：人物卡与事件卡是两套字段块（`src/app/cards.ts:85`、`src/app/cards.ts:136`）；卡内的关系、主将、相关人物、上级事件、生平事件都是可点链接，点完走同一条选中与定位逻辑（`src/app/app.ts:1517`）。
8. 视图控制：滚轮以指针为锚缩放、拖动平移、Shift 滚轮纵翻、`+` / `-` / 左右方向键、复位（`src/app/app.ts:1747`、`src/app/app.ts:1790`）、巡航 / 深空皮肤切换（`src/app/app.ts:1295`）、PNG 与 SVG 导出，导出画面含底部朝代带（`src/app/app.ts:1858`）。
9. 深链：`#<topic>/<view>`、`#<topic>`、`#<line>`、`#<line>/event/<id>`、旧链 `#wudi`；`hashchange` 重新解析（`src/routing.ts:49`、`src/app/app.ts:1593`）。
10. 状态持久化：皮肤、内容线、专题、事件条折叠、隐藏泳道分组写入 localStorage（`src/app/app.ts:49`）。
11. 无障碍：`aria-live` 播报（`src/app/app.ts:1094`）、键盘操作、地址落空给提示（`src/app/app.ts:1443`）、`prefers-reduced-motion`（`src/styles.css:709`）。

### 2.2 能力缺口

判定口径：只有代码是证据。G1、G2、G4 已兑现，列在下面的「已关闭」里当事实；G3、G5、G6、G7、G8、G9 仍缺，缩窄到具体缺在哪；G10–G12 是本轮读代码新发现的。

**仍然缺的。**

**G3 · 48 个分类不能筛。** `categories` 只在人物卡渲染成静态 chip（`src/app/cards.ts:95`、`src/app/cards.ts:123`）。src/ 里没有任何按 `categories` 过滤、配色或写进地址的代码；chip 生成的是不带 `data-kind` 的 `<span>`，点不动（`src/app/cards.ts:46`）。人物仍只能按专题泳道看，没有"谁是诗人、谁是名将、谁属法家"的横向视图。

**G5 · 事件视觉编码只落了 `importance` 一档。** `scale` 在画布上没有任何读取：`src/app` 里唯一的 `event.scale` 引用是事件卡徽标（`src/app/cards.ts:144`），不控制条宽、描边或布局。`parent` 不画隶属层级，只给一条上级事件链接（`src/app/cards.ts:162`、`src/app/cards.ts:187`）。`commanders.side` 只写成主将名后的括号政权名（`src/app/cards.ts:151`），交战方是一行 `／` 连接的名单（`src/app/cards.ts:183`），战役双方对不上位置。

**G6 · 没有筛选体系。** 当前只有顶栏 5 个 chip（`index.html:63`）与泳道面板的显隐勾选（`src/app/app.ts:1271`）。chip 是单选（`state.chip` 一个值，`src/app/app.ts:1539`）、只降透明度不过滤（`src/app/app.ts:447`、`src/app/app.ts:523`）、不进地址，且切内容线即复位（`src/app/app.ts:1166`）。分类、政权、类型、规模、重要性、朝代都没有多选筛选器。上一版写的「专题分面（region / era / theme）」和「事件线的朝代筛选」在当前前端**并不存在**：`filterTopics`（`src/contract.ts:318`）与 `TopicFilters`（`src/types.ts:231`）在 src/ 里没有调用者。

**G7 · 121 个政权不能筛。** 与 G3 同一口径：`polity` 只进人物卡（`src/app/cards.ts:124`），政权词表只用于把 `belligerents` 与 `side` 的 id 翻成中文（`src/app/model.ts:109`）。没有政权维度。

**G8 · 没有列表/目录视图。** `index.html` 没有列表或表格容器，src/ 没有卡片墙代码。2183 人 + 609 事件只能沿时间轴扫读。

**G9 · 人物线上的事件不可点，除非展开「事件条」。** 186 条段事件画成贯穿绘图区的背景带（`src/app/app.ts:323`），背景带不参与命中测试：人物线上只有「事件条」展开后、头部条带区域内的事件才点得中，而事件条默认折叠（`src/app/app.ts:127`、`src/app/app.ts:1019`）。事件也不随选中人物过滤。旧条目写的"军事线人物影子条只取前 12 人"已失效——当前实现没有人物影子条，事件线上不画人物。

**G10（新）· 事件→人物的关联没有画面反馈。** 选中人物会画关系曲线（`src/app/app.ts:343` 只在 `kind === 'person'` 时调用 `drawRelations`）；选中事件时画布不画、不亮它的 `people`。`eventsByPerson` 只提供单向能力（`src/app/model.ts:73`），事件→人物的反查只落在卡片文字里。

**G11（新）· 「女性」chip 在事件线上等于空白。** `chipMatchEvent` 对 `female` 一律返回 false（`src/app/app.ts:999`），于是事件线上每条事件都降到 0.15 透明度（`src/app/app.ts:447`）；人物线的事件背景带同时降到 `eventAlphaDim`，事件条整条被过滤掉（`src/app/app.ts:765`）。chip 之间也不能组合：战事 + 女性无法叠加。

**G12（新）· 视图状态不进地址。** 人物线只写专题与章节（`src/app/app.ts:1398`），事件线只写线或事件（`src/app/app.ts:1407`）。chip、泳道显隐、缩放视窗、皮肤都不落 URL；在人物线上选中事件时连地址都不写（`src/app/app.ts:1125`）。可分享的深链只有专题 / 章节 / 事件三种。

**已关闭的（留作事实，不再算缺口）。**

- **G1 人物与事件已互通。** 事件的人物引用在前端建成反向索引 `eventsByPerson`（`src/app/model.ts:73`），人物卡按年份列出这个人的事件、每条都是可点链接（`src/app/cards.ts:108`、`src/app/cards.ts:113`），点击走 `selectAndReveal` 打开事件卡（`src/app/app.ts:1517`）。人物卡不再读专题里的 legacy `topic.events`：该字段（`src/types.ts:192`）在 src/ 里已没有任何读取者。
- **G2 实体库这一层成立，独立入口不成立。** `src/` 只 fetch `index.json` / `military.json` / `history.json` / `search.json` 加当前专题文件（`src/app/model.ts:51`），`events.json` 这个文件确实没被加载。运行时把两条目录按 id 去重合成全量实体（`src/app/model.ts:63`）；实测并集恰为 609 条，与 `events.json` 完全一致，所以没有事件因此不可达。搜索、卡片、人物线事件带吃的都是这份全量。剩下的缺口只有入口：事件线一次只看一条目录（`src/app/app.ts:225`），历史事件线上不含 24 条只被军事目录引用的事件，也没有"全部事件"的连续视图。
- **G4 总览已经有了。** 底部带 = 26 朝代着色 + 事件密度 + 视窗框 + 点朝代跳转（`src/app/app.ts:860`、`src/app/app.ts:872`、`src/app/app.ts:1729`）。世纪分段按钮作为导航已删除：`segments` 只在载入时归一化（`src/loader.ts:67`），旧 `#<line>/<segment>` 链接只提示「世纪分段已由底部朝代带取代」（`src/app/app.ts:1438`）。

### 2.3 体验问题（页面表现）

1. **顶栏仍是两行。** 岛一行加快捷筛选一行（`index.html:21`、`index.html:63`），底部固定 76px 朝代带（`src/styles.css:11`）；绘图区高度等于视口减两者，由代码把实测值写回 `--topbar-h`（`src/app/app.ts` 的 `resize()`）。上一版写的 briefbar 与常驻图例条在当前界面里已经不存在。
2. **章节藏在弹层里。** 章节按钮和泳道勾选共用一个泳道面板（`src/app/app.ts:1262`），点章节要先开面板；事件线没有章节。
3. **事件线的留白靠拉伸补。** 内容不足一屏时行距最多放大到 4 倍填充高度（`src/app/app.ts:240`、`src/app/app.ts:244`）；行仍按 `type` 固定（`src/app/layout.ts:55`），没有按密度决定行高的控制。
4. **看不全"当前生效什么筛选"。** chip 的选中态在顶栏可见，被隐藏的泳道只有面板打开时才看得见，切内容线还会把 chip 复位（`src/app/app.ts:1166`）。
5. **卡片字段仍是文本堆叠。** 人物卡与事件卡已拆成两套，但交战方、主将阵营、规模、上级事件都排成文字行（`src/app/cards.ts:183`、`src/app/cards.ts:184`），没有分侧或分组布局。

## 三、重设计：信息架构

### 3.1 核心判断

原架构是「一个专题一份 JSON、一个页面一条时间轴」。数据现在长到 2183 人 + 609 事件 + 26 朝代 + 48 分类 + 121 政权。这个尺度下，专题切换不该是主要导航动作，筛选才是。

新架构：

```
一个实体库（人 2183 + 事 609）
        ↓
   一套统一筛选器
        ↓
   三种视图（时间轴 / 关系 / 列表）
        ↓
   一个详情抽屉
```

三条内容线（人物 / 军事 / 历史事件）降级为**筛选器的第一个维度**，不再是三套独立的页面状态机。

### 3.2 统一筛选器

一组筛选条件，三种视图共用，切换视图时条件保留。

| 维度 | 取值 | 适用于 |
|---|---|---|
| 线 | 人物 / 军事 / 历史事件 / 全部 | 全部 |
| 时间 | 26 个朝代区间（可重叠）+ 年份区间刷选 | 全部 |
| 分类 | 48 个（多选） | 人物 |
| 政权 | 121 个（多选） | 人物 + 事件 |
| 类型 | 6 个 | 事件 |
| 规模 | war / campaign / battle / engagement | 事件（type=军事） |
| 重要性 | 1 / 2 / 3 | 事件 |
| 性别 | 女 / 男 / 不详 | 人物 |
| 关键词 | 姓名、称号、别名、标签 | 全部 |

每个维度显示命中数。筛选结果实时反映在主视图和计数上。

### 3.3 视图

**V1 时间轴（默认）**
横轴 = 年份，纵轴 = 行。支持三种行模式：
- 人物模式：按泳道分组（帝王 / 后妃 / 文臣 / 武将 / …）。
- 事件模式：按 `type` 分行；`importance` 编码为标记大小，`scale` 编码为条宽/描边，`kind` 决定点或段，`parent` 用连接线表达隶属。
- 同框模式（新）：人物泳道作前景，关联事件作背景带；点人物高亮其关联事件，点事件高亮其关联人物。这是 G1 的落点。

**V2 关系**
以焦点人物为中心的 1 跳 / 2 跳图。保留现有实现，增加按关系类型筛选、按分类着色。

**V3 列表**
承接 2183 人 / 609 事件的规模。按当前筛选出卡片墙或表格，可排序（生年 / 卒年 / 年份 / 重要性 / 分类）。点条目跳回时间轴并聚焦。这是 G8 的落点。

## 六、视觉方向

三个候选方向，需要定一个。

**方向 A · 现代学术出版（推荐）**
- 浅色底（近白 + 极浅暖灰分区），无装饰、无渐变。
- 标题用衬线中文字体（宋 / Source Serif），数据标签用无衬线，字号分级严格。
- 主色：墨黑 + 一个强调色（赭石或朱砂）。
- 48 个分类归入 6 个色族（统治 / 军政 / 文士 / 思想 / 技艺 / 方外），每族 3–4 阶明度，保证 48 类可区分又不花。
- 事件 6 类沿用现有 type 色，但降低饱和度；`importance` 用尺寸，`scale` 用描边粗细。
- 网格线极细，留白充足。
- 优点：承载 2183 人的密度而不乱；分类配色有系统；导出成图仍然耐看。
- 风险：需要设计 48 类的色族映射表。

**方向 B · 深色档案库**
- 深炭底（#14120f 系），高饱和分类色，细网格。
- 信息密度最高，长时间看眼睛负担小。
- 优点：分类色和事件色在深色上区分度最好；有"数据库"质感。
- 风险：PNG 导出和打印效果差；中文宋体在深色上需要调字重。

**方向 C · 沿用现有古籍调性，只改结构**
- 保留宣纸米色 + 宋体 + 现有色板，只做第四章的结构改造（左侧栏 + minimap + 详情抽屉 + 列表视图）。
- 优点：改动最小，风险最低，导出效果已验证。
- 风险：48 分类、6 规模、3 重要性的视觉编码无处安放；"页面表现不够满意"可能没解决。
