## 一、数据现状（管线已产出，前端可以直接吃）

`public/data/` 共 22 份 JSON。

|---|---|---|
| `index.json` | 目录。17 专题 + 3 内容线 + 词表 | 48 分类 / 101 政权 / 26 朝代 / 17 eras / 2 themes / 1 region |
| `<topic>.json` × 17 | 人物专题。每人一条 | 2158 人（跨专题去重后） |

## 二、前端现状盘点

### 2.1 已经能跑的功能

1. 三条内容线切换：人物 / 军事 / 历史事件。
2. 人物线：泳道分组、生卒条四种可信度画法（精确 / 约略 / 异说 / 不详开放条）、关系曲线、专题事件带、章节（view）镜头。
3. 事件线：按 `type` 分行、世纪分段导航、朝代筛选、军事线人物影子条。
4. 搜索：专题内优先，落空后查全局索引；人物与事件混排；支持跨专题跳转。
5. 关系全景：以焦点人物为中心的 1 跳图，点邻居换中心，Esc 返回。
6. 卡片：人物卡（生卒 + 简介 + 标签 + 关系 + 关联事件）、事件卡（时间 + 地点 + 交战方 + 主将 + 出处）。
7. 视图控制：缩放、平移、复位、导出 PNG / SVG。
8. 深链：`#topic/view`、`#line/segment`、`#line/event/<id>`；旧链兼容。
9. 无障碍：`aria-live` 播报、键盘操作、`route-miss` 兜底、reduced-motion。

### 2.2 能力缺口（数据有，前端没有）

按价值排序：

**G1 · 人物与事件没有互通。** `events.json` 里 346 条事件挂了 855 个人物引用，全部有效。人物卡只显示专题内的 legacy `topic.events`（汉 29 条、唐 11 条，是旧格式），看不到全局事件库。事件卡能跳人物，人物卡不能跳事件。这是这批数据最大的未兑现价值。

**G2 · `events.json` 从未被加载。** 464 个事件实体只有被 military / history 两个目录引用时才可见。没有"事件实体库"入口，没有跨目录的事件主页，也没有"全部事件"的连续视图。

**G3 · 48 个分类完全没有渲染。** 1988 人带分类，前端既不筛选也不配色。人物只能按泳道看，不能按"谁是诗人、谁是名将、谁属法家"横向看。

**G4 · 没有总览。** 4020 年跨度只靠章节按钮和缩放定位，没有 minimap、没有朝代带、没有"我在哪儿"的空间反馈。事件线的 28 / 32 个分段按钮横排，只能横滚，看不出全局分布。

**G5 · 事件视觉编码不足。** `importance`（1-3）和 `scale`（战争/战役/会战/交锋）都不参与布局与绘制。`parent` 层级不显示。主将的 `side`（阵营）不显示，战役双方对不上。

**G6 · 没有筛选体系。** 现在只有：专题分面（region / era / theme，且只筛专题）+ 事件线的朝代筛选。分类、政权、类型、规模、重要性都不能筛。

**G7 · 政权（101 个）没有渲染。** 人物归属政权是数据里第二丰富的维度，前端零使用。

**G8 · 没有列表/目录视图。** 2158 人 + 464 事件只能沿时间轴看，没有可排序、可扫读的卡片墙或表格。

**G9 · 细节未用字段。** 事件别名（379 条）不参与搜索；出处不按 `kind` 分组；`placeNow`（197 条）没有地理维度；军事线影子条只取前 12 人且是灰色装饰，不可筛选。

### 2.3 体验问题（页面表现）

1. **Chrome 吃掉太多垂直空间。** 顶栏一套（线 tab + 专题下拉 + 章节 + 搜索 + 6 个按钮），下面 briefbar 一条，底部图例常驻一条。绘图区被压到中间一条。
2. **章节导航退化。** 事件线 28 / 32 个分段按钮横排，无法一眼看清，只能横滚。分段成了唯一导航手段。
3. **事件线留白严重。** 行高 38–64px，一个分段常常只有几件事，屏幕大面积空。
4. **筛选藏在弹层里。** 分面筛选在专题下拉的浮层内，选完就收起，看不到"当前生效什么筛选"。事件线的朝代筛选藏在同一个浮层里。
5. **卡片模板单一。** 人物卡和事件卡共用一套样式，事件卡的交战方 / 阵营 / 规模 / 层级挤在"标签"里。
6. **视觉调性与数据规模不匹配。** 米色宣纸 + 宋体的"古籍"调性，服务于当初"一个朝代几十人"的尺度。现在是多线、多分类、多政权的结构化数据库，色板仍是泳道 / type 两套固定色，48 个分类、6 种规模、3 档重要性都没有对应编码。

## 三、重设计：信息架构

### 3.1 核心判断

原架构是「一个专题一份 JSON、一个页面一条时间轴」。数据现在长到 2158 人 + 464 事件 + 26 朝代 + 48 分类 + 101 政权。这个尺度下，专题切换不该是主要导航动作，筛选才是。

新架构：

```
一个实体库（人 2158 + 事 464）
        ↓
   一套统一筛选器
        ↓
   三种视图（时间轴 / 关系 / 列表）
        ↓
   一个详情抽屉
```

三条内容线（人物 / 军事 / 历史事件）降级为**筛选器的第一个维度**，不再是三套独立的页面状态机。

### 3.2 统一筛选器

一组筛选条件，三种视图共用，切换视图时条件保留。

| 维度 | 取值 | 适用于 |
|---|---|---|
| 线 | 人物 / 军事 / 历史事件 / 全部 | 全部 |
| 时间 | 26 个朝代区间（可重叠）+ 年份区间刷选 | 全部 |
| 分类 | 48 个（多选） | 人物 |
| 政权 | 101 个（多选） | 人物 + 事件 |
| 类型 | 6 个 | 事件 |
| 规模 | war / campaign / battle / engagement | 事件（type=军事） |
| 重要性 | 1 / 2 / 3 | 事件 |
| 性别 | 女 / 男 / 不详 | 人物 |
| 关键词 | 姓名、称号、别名、标签 | 全部 |

每个维度显示命中数。筛选结果实时反映在主视图和计数上。

### 3.3 视图

**V1 时间轴（默认）**
横轴 = 年份，纵轴 = 行。支持三种行模式：
- 人物模式：按泳道分组（帝王 / 后妃 / 文臣 / 武将 / …）。
- 事件模式：按 `type` 分行；`importance` 编码为标记大小，`scale` 编码为条宽/描边，`kind` 决定点或段，`parent` 用连接线表达隶属。
- 同框模式（新）：人物泳道作前景，关联事件作背景带；点人物高亮其关联事件，点事件高亮其关联人物。这是 G1 的落点。

**V2 关系**
以焦点人物为中心的 1 跳 / 2 跳图。保留现有实现，增加按关系类型筛选、按分类着色。

**V3 列表**
承接 2158 人 / 464 事件的规模。按当前筛选出卡片墙或表格，可排序（生年 / 卒年 / 年份 / 重要性 / 分类）。点条目跳回时间轴并聚焦。这是 G8 的落点。

## 四、页面结构

```
┌────────────────────────────────────────────────────────────────────┐
│ 顶栏 56px                                                            │
│  品牌 · 三条线 tab · 全局搜索（人+事） · 视图切换 · 导出              │
├──────────┬─────────────────────────────────────────┬───────────────┤
│ 左侧栏   │  主视图                                  │ 详情抽屉      │
│ 272px    │                                         │ 360px         │
│ 可折叠   │  ┌───────────────────────────────────┐  │               │
│          │  │  时间轴 / 关系 / 列表              │  │ 人物卡        │
│ 筛选器   │  │                                   │  │ 或            │
│ ─ 朝代   │  │                                   │  │ 事件卡        │
│ ─ 分类   │  │                                   │  │               │
│ ─ 政权   │  │                                   │  │ （可折叠）    │
│ ─ 类型   │  │                                   │  │               │
│ ─ 规模   │  └───────────────────────────────────┘  │               │
│ ─ 重要性 │  ┌───────────────────────────────────┐  │               │
│          │  │  minimap：全时段朝代带 + 视窗框    │  │               │
│ 命中计数 │  └───────────────────────────────────┘  │               │
│ 清除筛选 │                                         │               │
├──────────┴─────────────────────────────────────────┴───────────────┤
└────────────────────────────────────────────────────────────────────┘
```

### 4.1 逐块说明

**顶栏（56px，单行）**
- 左：品牌「历史时间轴」+ 当前线标题。
- 中左：三条线 tab（人物 / 军事 / 历史事件）。
- 中右：全局搜索。占位提示改为「搜索人物或事件」。结果面板分组显示「人物」「事件」。别名参与匹配。
- 右：视图切换（时间轴 / 关系 / 列表）+ 导出菜单。

删除：顶栏的章节按钮行、专题下拉。两者分别移到 minimap 和左侧栏。

**左侧栏（272px，可折叠）**
- 筛选器分组：朝代、分类、政权、类型、规模、重要性。
- 每组显示命中数；已选项显示为实心 chip。
- 顶部显示「命中 N 人 / M 事」，底部常驻「清除筛选」。
- 朝代组同时是专题入口：点朝代等于限定该时段的专题范围。

**主视图**
- 时间轴占满剩余空间。顶部的 sticky 年份轴保留。
- 底部固定 64px 的 **minimap**：一条 -2070 → 1949 的横向带，26 个朝代按区间着色分段并标注；当前视窗画一个可拖动的框；轴上按事件密度画细密的 tick，密度即分布。
- minimap 替代原来的 28 / 32 个分段按钮：拖动框 = 平移，拖框边缘 = 缩放，点朝代 = 跳到该区间。

**详情抽屉（360px，可折叠）**
- 人物卡：生卒（含可信度说明）、分类 chip（可点，反查同类）、政权、称号、简介、标签、关系列表、**生平年表**（由 `events.json` 反查，可点跳事件）、动作（关系全景 / 在时间轴定位）。
- 事件卡：时间（含可信度）、地点（古地名 + 今地）、类型 + 规模 + 重要性徽标、**交战方（按 `side` 分两侧着色）**、主将（带阵营徽标，可点跳人物）、结果、描述、上级事件（可点）、相关人物、**出处（按 `kind` 分组：典籍 / 现代考证 / 外部数据库）**。

删除：底部的常驻图例条。图例改为抽屉内的说明块 + 主视图右上角的悬浮按钮。

## 五、交互设计

## 六、视觉方向

三个候选方向，需要定一个。

**方向 A · 现代学术出版（推荐）**
- 浅色底（近白 + 极浅暖灰分区），无装饰、无渐变。
- 标题用衬线中文字体（宋 / Source Serif），数据标签用无衬线，字号分级严格。
- 主色：墨黑 + 一个强调色（赭石或朱砂）。
- 48 个分类归入 6 个色族（统治 / 军政 / 文士 / 思想 / 技艺 / 方外），每族 3–4 阶明度，保证 48 类可区分又不花。
- 事件 6 类沿用现有 type 色，但降低饱和度；`importance` 用尺寸，`scale` 用描边粗细。
- 网格线极细，留白充足。
- 优点：承载 2158 人的密度而不乱；分类配色有系统；导出成图仍然耐看。
- 风险：需要设计 48 类的色族映射表。

**方向 B · 深色档案库**
- 深炭底（#14120f 系），高饱和分类色，细网格。
- 信息密度最高，长时间看眼睛负担小。
- 优点：分类色和事件色在深色上区分度最好；有"数据库"质感。
- 风险：PNG 导出和打印效果差；中文宋体在深色上需要调字重。

**方向 C · 沿用现有古籍调性，只改结构**
- 保留宣纸米色 + 宋体 + 现有色板，只做第四章的结构改造（左侧栏 + minimap + 详情抽屉 + 列表视图）。
- 优点：改动最小，风险最低，导出效果已验证。
- 风险：48 分类、6 规模、3 重要性的视觉编码无处安放；"页面表现不够满意"可能没解决。

## 七、实施分期

建议先补能力，再换皮。数据结构与视图逻辑改完，视觉换肤是最后一公里。

| P4 | 时间轴同框模式（人物 + 事件叠加互高亮）；`importance`/`scale` 视觉编码 | G1 G5 |
| P5 | 列表视图 | G8 |
| P6 | 视觉换肤（按选定方向）；图例收起；卡片模板拆分 | 体验问题 1/5/6 |

## 八、待确认

1. **视觉方向**：A 现代学术出版 / B 深色档案库 / C 沿用古籍调性。
2. **重构范围**：在现有 `src/` 上渐进改造，还是重写 `src/`（保留 `pipeline/` 与数据契约）。
3. **优先级**：先补数据能力（P1–P3），还是先改视觉（P6）。
4. **同框模式**（人物 + 事件叠加在同一条轴上）：是否作为默认视图。这条改动最大，也最能兑现数据价值。
5. **移动端**：现有 640px / 900px 断点下的抽屉方案是否保留。

## 九、落地记录（2026-10-09）

`prototype/1008/dual`（巡航 + 深空双皮肤）已移植到 `src/`，作为站点唯一前端。数据契约与 `pipeline/` 未改。

**已落地**

- 顶栏：品牌、三条内容线、专题下拉、搜索、泳道面板、复位、导出、皮肤切换、快捷筛选。
- 主视图：canvas 时间轴。人物线按泳道分行，军事 / 历史事件线按事件 `type` 分行，`kind` 决定点或段、`importance` 决定标记大小。
- 吸顶头部：年轴带朝代色块与年份刻度；人物线可展开事件条带（按像素距离聚合）。
- 底部：全时段朝代带 + 事件密度 + 可拖动、可拉伸的视窗框，替代原来的世纪分段按钮。
- 详情抽屉：人物卡（生卒、分类、政权、标签、简介、关系、由 `events.json` 反查的生平事件）与事件卡（时间、地点、交战方、主将阵营、规模 / 重要性徽标、上级事件、按 `kind` 分组的出处）。
- 深链：`#<topic>/<view>`、`#<topic>`、`#<line>`、`#<line>/event/<id>`、旧链 `#wudi` 全部可用，并在 `hashchange` 时重新解析。
- 导出：PNG 走 2 倍离屏重绘；SVG 目前把同一张位图内嵌进 `<image>`。
- 状态持久化：皮肤、内容线、专题、事件条带折叠、隐藏泳道分组存放。

**与原设计的差异**

- 人物线仍是「一次看一个专题」，不是全部 2158 人合并成一条轴。泳道 id 在不同专题里含义不同（例如 `scholar`），合并会错标；专题切换由顶栏下拉和底部朝代带共同承担。
- 原「关系全景」独立视图不再单列。关系改为选中人物后直接画在轴上，这是原型的行为；跨专题关系仍没有数据基础。
- 左侧常驻筛选栏改成顶栏快捷筛选 + 泳道面板，分类 / 政权目前只用于卡片展示，未做成多选筛选。
- 导出 SVG 是位图内嵌，还不是矢量重绘。

3. 导出改矢量 SVG。
