## Design Specificity Verdict

**LLM assessment**：视觉是为读史写的。宣纸底、宋体人名、墨色章节胶囊、泳道色和「前880」刻度，换一套销售数据用不上。信息架构仍是图表控制台：缩放、全部关系、复位、导出和自动打开的人物卡，压过「谁和谁同时活着」。`#han/wudi` 和「国人与共和」像一章书；默认的西周全览像一张把大多数人压暗的索引。

**Deterministic scan**：对 `index.html` 和 `src/` 的 CLI 扫描退出码 0，finding 为 0。第一次因缺少 HTML 解析器走了正则降级，补上解析器重跑仍是 0；对照文件能报出问题，所以这不是扫描没跑起来。运行时注入才看见问题：桌面首页 11 条，`#han/wudi` 16 条，儒学 7 条，390px 首页 28 条。实打实的是提示和副标题过小（10.5–11.5px）、卡片注释对比度约 4.1:1、年份标签 10.5px。检测器没碰到这次真正伤读者的行为：默认聚焦压暗、滚轮当缩放、搜索范围、坏链改写。

**Visual overlays**：注入发生在无头 Chrome 里，没有留在你正在看的浏览器上。不要到页面里找高亮框。

检测器里这几条不当成产品问题：`cream-palette` 把有意的纸色底当成通用米色模板；三处「细边框加大阴影」打在默认隐藏的专题菜单、搜索结果和导出菜单上；卡片滚动区伸到图例下面的「被遮挡」是溢出盒，字并没有画在图例上。390px 上大量「文字被卡片挡住」是同一件事重复计数：卡片是浮层，默认又开着，所以时间轴被盖住。这是真问题，但不是十九条互相叠字。

## Overall Impression

材质和章节镜头是对的。读者第一次进来，以及在手机上，图本身退到了后面。最大的机会是让默认落在能一屏读完的一章，全览退成索引。

## What's Working

- `#han/wudi` 把故事摆对了。武帝的长条横贯这一章，霍去病、卫青的短条落在他的年份里，右卡写明生年有前 156、前 157 两说。
- 「国人与共和」只有几个人。简介直接讲召穆公、周定公和共伯和抢的是同一段空白，这才是这个产品的阅读单位。
- 关系全景是可读的色环，颜色对得上图例，「返回时间轴」和 Esc 都能回来。专题里搜「刘彻」，结果会标出「汉武帝 / 刘彻」和生卒，回车把视野收到他身上。

## Priority Issues

### [P0] 默认全览又压暗，又画不出简介说的寿命对照

进入 `#xizhou/overview` 就聚焦周宣王。不在他一跳关系里的人被画成 0.22 透明度。生年不详的条用固定约 56px 的开口（`OPEN_STUB`），左右是箭头，长度不随缩放变成「活了多少年」。简介却写「宣王的条横贯中兴，幽王的条短而止于镐京——三王的长度本身就是西周怎么完的」。唐全览同样会把大多数人压暗。再打开「显示全部关系」，弧线叠上整列人名。

**Why it matters**：读者要看的是同时代。第一眼得到的是一个已经选中的人，加上一排不能互相比较的短条。

**Fix**：全览默认不聚焦、不压暗。未知生卒改成明确的「只知卒年」标记，不要占一行假装有一段可比较的寿命。默认落地改成能一屏读完的章节，全览当索引。

**Suggested command**：`$impeccable distill`

### [P0] 手机首屏被卡片盖住，单指还不能往下看人名

390px 宽时，章节的焦点人物会自动打开底部卡片（`max-height: 58vh`）。实测卡片大约从纵轴 321px 起到 811px，时间轴只剩一条年份刻度，一个人名都没有。图区 `touch-action: none`，单指上下拖动不滚动列表。底栏图例在 390px 里内容宽约 900–1062px，「年代」和几种关系要横滑才看得到。汉代在窄屏下第五章「西汉末 · 新莽代汉」也会被章节条裁掉。

**Why it matters**：手机上的第一任务是看图。现在第一屏是周宣王的传记，图几乎不在。

**Fix**：窄屏不要自动开卡。卡做成不超过半屏的抽屉，先留出年份和至少一条泳道。单指纵向滚动人名，捏合才缩放。图例改成可点开的分组。

**Suggested command**：`$impeccable adapt`

### [P1] 滚轮、拖动和年份轴互相拆台

在图上滚动会缩放，页面不往下走。要按住 Shift 或 Alt 再滚，人名列表才动。纵向拖动不产生滚动。放大后横拖能平移年份，但年份轴和泳道名是整张 SVG 的一部分，滚到中段就离开视口，屏上没有「现在是哪一年」。复位只恢复时间范围，不回到列表顶部，也不关掉「显示全部关系」。

**Why it matters**：一百多行的全览，往下看人名是主操作。现在主操作被做成了缩放，年份这个唯一坐标还跟着走丢。

**Fix**：滚轮默认滚人名，Ctrl/⌘ 或捏合才缩放。年份轴固定在图顶。纵向拖动应滚动。复位连同关系开关和滚动位置回到这一章的默认。

**Suggested command**：`$impeccable layout`

### [P1] 搜索把「不在这一册」说成「没有这个人」

在西周搜「孔子」「刘彻」和「不存在的人zzz」，都是「没有匹配的人物」。孔子在儒学专题里能命中。占位符只写「搜索人物」，不写范围。结果有时靠标题命中（子思的标题含「孔子」），行上仍只显示姓名和生卒，看不出为什么出现。

**Why it matters**：读者会以为站点没有孔子。他只是不在当前这 128 人里。

**Fix**：空状态写成「西周没有『孔子』」。其他专题有的话，列出专题名并能跳过去。占位符改为「搜索本专题人物」。命中行带上命中的称号。

**Suggested command**：`$impeccable clarify`

### [P1] 走错的链接和返回键都不说实话

`#not-a-topic/foo` 被改成 `#xizhou/overview`，`#han/missing-view` 被改成汉代全览。没有错误条。读屏只听到进入了一个他没点的章节。站内换章节不增加历史记录，浏览器返回跳过刚才那一章。选中人物也不会进地址，复制 `#han/wudi` 可以，复制「当前这个人」不行。

**Why it matters**：分享和走错路是读者的正常动作。现在两条都会静默落到另一张图上。

**Fix**：未知专题或章节留下原地址，图区写出缺少的名字，并给「回到西周」或相近章节。站内切换用 `pushState`。

**Suggested command**：`$impeccable harden`

## Cognitive Load

8 项里 7 项失败，负荷高。

- 单一焦点：失败。章节、搜索、右卡、图、全部关系同时在场。
- 组块不超过 4：失败。工具始终 5 个；汉代和唐各 5 章；专题菜单一次放出约 22 个筛选芯片和 16 个专题。在「清」里打开菜单，当前项在折叠区域下面，滚动仍停在顶部。
- 相关项分组：通过。顶栏、简介、图、右卡、底图例边界清楚。
- 视觉层级：失败。默认右卡和压暗的图分不出谁是正文。
- 一次一件事：失败。
- 少记状态：失败。要记住修饰键、变淡的含义、搜索范围，以及滚走之后的年份。
- 用读者的词：失败。图例写「泳道」；「复位」「视野」「关系全景」要先翻译。
- 渐进披露：失败。缩放、导出、全部关系、三组分面都在第一层。

## Emotional Journey

- 第一眼：纸面安静，右卡已经是周宣王，图上多数人是淡的，不知道先读图还是先读卡。
- 读懂一章：点进「国人与共和」或 `#han/wudi` 会松一口气，条、事件和简介是同一件事。
- 点开一个人：tooltip 有名字和岁数，卡片有异说和关系注。再点一次同一个人，卡没了。
- 在密图里迷路：全览高三千多像素，滚轮在放大，年份轴滚没了。
- 手机上放弃：卡片盖住图，单指拖不动，图例还要横滑。

## Persona Red Flags

**Jordan（第一次打开）**

- 落地就是周宣王的卡片，图例小标题是「泳道」，多数条是淡的开口箭头，简介里的「条横贯」对不上图。
- 悬停另一个人时，tooltip 换了，右卡仍是宣王。
- 在西周搜「孔子」，和乱码得到同一句「没有匹配的人物」。

**Casey（手机单手）**

- 关闭按钮在卡片右上，图只剩一截「前880…前800」，年份右边被裁切。
- 单指上下拖不动人名。提示没有说要先关卡片。
- 底栏「年代」和后几种关系在首屏外面。

**Sam（只键盘和读屏）**

- Tab 的顺序是整张图的一百多个人物按钮，每个焦点还记到两次。卡片排在这些按钮之后。
- `svg` 是 `role="img"`，里面又放着这些按钮。人物按钮的名字带负年份，例如「周厉王，生年不详至-828」。
- 坏链没有错误提示，只宣布进入了一个他没请求的章节。Esc 能关菜单和关系图，不关卡片。

## Minor Observations

- 全览事件标题有重叠，旁边出现「+5」。测到「国人暴动，厉王奔彘」和「共和行政」等标签的包围盒相交。

- 朝代芯片不是时序：西周、春秋、战国、西汉、秦、东汉。地区只有「全部 / 中国」。
- 当前专题的选中底和悬停底是同一种米色，没有勾号。
- 「约略」渐变和「生卒不详」的开口，在 56px 短条上几乎看不出差别。
- 卡片注释 `#7d7466` 在 `#f7f1e6` 上约 4.1:1，低于正文常用的 4.5:1。提示条约 10.5px。
- 有人物的卡片在桌面要在卡片内部再滚很久才能看完关系。
- 控制台没有业务报错。数据真加载失败时才有红色错误块；走错 hash 走不到那里。
